# APStudio: затенение Topbar и Sidebar

Проверенная цепочка: `studio.js` → sparse `components` → personal API/сохранение → `af_aa_postbit_compile()` → `--aa-topbar-mask` / `--aa-sidebar-mask` → фон соответствующего ATF-контейнера.

Выявленные разрывы:

- Компилятор строил маску только при наличии `overlay_mode` (либо старого `darkening`). Изменение интенсивности, цвета или градиента при наследуемом режиме оставляло сохранённые значения без эффекта.
- Ползунки без собственных значений показывали минимумы (`0`), хотя компилятор использовал интенсивность `.5`, начало/конец `1`, угол `180`. Можно было незаметно сохранить два прозрачных конца градиента.
- CSS компонентов в APStudio подключался без ревизии URL; браузер мог продолжать использовать старые правила ATF после обновления файлов.

Исправление использует прежнюю маску в `background-image`, без новых псевдоэлементов/оверлеев. Значения по умолчанию общие для UI и компилятора. Редактирование параметра при наследуемом режиме включает `darken`. Компилятор поддерживает и уже сохранённые sparse overrides. Явное `none`, нулевые значения и совместимость с `darkening` сохраняются. При явном отключении параметры маски недоступны в UI, пока не выбран другой режим. Стили предпросмотра получают ревизию по содержимому файла.

Topbar и Sidebar имеют разные переменные, задаваемые на собственных контейнерах. Не изменены `opacity`, `filter`, `transform`, `z-index`, слои анимации, содержимое и DOM аватаров. Фоновая маска не участвует в hit-testing, не закрывает ссылки или текст и рисуется в границах фона контейнера.

Проверки:

- `appearance_postbit_settings_regression.php`: обе зоны, sparse override, явный `none`, приоритет старого `darkening`, существующие настройки/шрифты/изображения.
- `appearance_overlay_browser.cjs`: значения ползунков, изменение интенсивности без предварительного выбора режима, darken/lighten, градиент, изоляция зон, сохранение/активация и тот же фон через обычный runtime-компилятор; клики, аватары и рамка; отключение маски.
- `appearance_studio_integration.php`: существующее сохранение, валидация и предпросмотр.

## Полная интенсивность и насыщенность фонового изображения

Интенсивность теперь задаёт общую силу маски. Для каждого конца градиента непрозрачность вычисляется как `I × (S + (1 − S) × I)`, где I — интенсивность, S — распределение градиента. При I=0 маска прозрачна, при I=1 полностью непрозрачна независимо от прежних мягких концов; промежуточные значения меняются плавно. Концы UI переименованы в «Градиент затенения», чтобы не выдавать относительные значения за итоговую прозрачность. Сохранённые значения не переписываются. Цветом остаётся выбранный цвет маски (чёрный для обычного затемнения).

`background_saturation` (0…100, по умолчанию 100) доступен для фона верхней панели, сайдбара и сообщения. В ATF добавлен отдельный серый слой смешивания `saturation`, расположенный ниже маски/дымки/цветовых акцентов и выше изображения. Это не фильтр контейнера: текст, аватары, рамки и анимационные DOM-слои сохраняют свои цвета и обработчики. При 100 слой прозрачен; при 0 цветное изображение становится серым. Без новой настройки прежнее оформление сохраняется.

`appearance_background_paint_fixture.php` + `appearance_background_paint_browser.cjs` проверяют реальные пиксели всех трёх зон: чёрный при 100% затенения даже с концами 30%, исходный красный при насыщенности 100%, промежуточный при 50% и серый при 0%. `appearance_overlay_browser.cjs` проверяет сохранение насыщенности через обычный API и её применение в runtime. Версии AA/ATF повышены для доставки обновлённых ресурсов.
