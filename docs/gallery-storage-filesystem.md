# Точная статистика тома в ACP Gallery

Статистика оригиналов Gallery остаётся отдельным SQL-показателем и не меняет пользовательские квоты. Общая занятость файловой системы включает все данные на томе и не приравнивается к файлам Gallery.

## Подключение для warprift.ru

После загрузки исходников реактивировать AdvancedGallery для добавления двух настроек (существующие значения сохраняются):

- **Ожидаемая точка монтирования хранилища** (`af_advancedgallery_storage_mount_path`): `/var/www/meowbaka1/data/www/warprift.ru/uploads`. Если `uploadspath` уже указывает сюда, пустое значение даёт ту же проверку.
- **Ожидаемое устройство хранилища** (`af_advancedgallery_storage_mount_device`): `/dev/sda1`. Необязательная дополнительная защита от подмены подключённого устройства.

Эти настройки только проверяют подключение: они ничего не монтируют, не меняют путь загрузки или настройки ext4. Для обычного каталога на общем диске администратор должен явно указать фактическую точку монтирования (например `/`), чтобы не принять отвалившийся сетевой том за основной диск.

Проверяется существующий каталог `realpath(uploadspath/af_gallery)` и наиболее глубокая содержащая его точка из `/proc/self/mountinfo` в пространстве монтирования PHP. Она должна совпадать с ожидаемой. В интерфейсе показаны каталог, точка монтирования, устройство и тип ФС. После сбора метрик подключение проверяется повторно, чтобы обнаружить отключение/замену тома во время запроса. При отсутствии каталога, недоступном mountinfo или несовпадении устройства/точки — предупреждение, без статистики корневого диска.

## Блоки, резерв и доступность

Для Linux используется GNU coreutils `stat --file-system --format='%S %b %f %a' -- <каталог Gallery>` через `proc_open` с массивом аргументов, без shell. Команда читает `statfs(2)` без обхода файлов, root и sudo. Фиксированные исполняемые пути `/usr/bin/stat` и `/bin/stat`; время ожидания ограничено двумя секундами.

| Показатель | Расчёт |
| --- | --- |
| Полная ёмкость ФС | `f_blocks × f_frsize` |
| Фактически занято | `(f_blocks − f_bfree) × f_frsize` |
| Доступно обычному процессу (Avail) | `f_bavail × f_frsize` |
| Свободный резерв | `(f_bfree − f_bavail) × f_frsize` |
| Progress bar | `фактически занято / полная ёмкость × 100` |

Резерв показывает **свободные** блоки, недоступные обычному процессу, а не полный настроенный размер reserved blocks ext4. На других ФС разность может отражать их механизмы ограничения доступности; интерфейс не называет её параметром конфигурации ext4.

При ёмкости 100 ГиБ, занятости 29 МиБ и свободном резерве 5 ГиБ интерфейс показывает:

- Полная ёмкость: `102 400,00 МиБ`.
- Фактически занято: `29,00 МиБ`.
- Доступно процессу PHP: `97 251,00 МиБ`.
- Свободный резерв: `5 120,00 МиБ`.
- Progress bar: около `0,0283%`.

Единицы подписаны как МиБ (1 048 576 байт). `disk_total_space − disk_free_space` больше не используется для определения занятости.

Если `proc_open` запрещён, GNU stat отсутствует или точные счётчики некорректны, после подтверждения подключения можно показать только независимо полученные ёмкость и доступное PHP пространство. Занятость, резерв и progress bar отсутствуют; причина указана в ACP. Если PHP также не может получить эти значения, они не выводятся.

## Проверки

```sh
php tests/gallery_storage_disk_regression.php
php -d disable_functions=proc_open tests/gallery_storage_disk_regression.php --no-stat
```

Проверяются пример ext4 с 29 МиБ/5 ГиБ, формулы и progress bar, совпадение с живым `df -B1 --output=size,used,avail`, mountinfo с отдельным ext4/NFS, экранированные пути, отсутствие ожидаемого подключения, неверное устройство и отключённый proc_open. Монтирование тестовых томов и повышенные привилегии не нужны. Пример ext4 использует контрольные счётчики; к production-серверу тест не подключается.

Существующие `gallery_media_api_integration.php --storage` и `gallery_storage_runtime_regression.cjs` проверяют сохранение квот, реактивацию и индикатор пользователя.
