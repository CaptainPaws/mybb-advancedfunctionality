# AdvancedEditor 1.1.6 / AdvancedGallery 1.2.2: общий медиапикер

Причина исчезновения Gallery: старый runtime регистрировал команду непосредственно
в SCEditor, тогда как AdvancedEditor теперь компилирует собственный единый тулбар
и лениво создаёт SCEditor. Новая интеграция регистрирует команду в реестре
AdvancedEditor; второй тулбар не создаётся.

## Интерфейс

«Изображение» и «Галерея» используют один экземпляр окна AdvancedGallery:

- **URL**: вставка `[img]URL[/img]` без создания записи Gallery. Разрешены
  HTTP/HTTPS-ссылки. PHP не запрашивает и не загружает этот URL.
- **Мои изображения**: существующий собственный медиакаталог, альбомы, поиск
  и фильтры источника. Запрашивается `picker_data` с `images_only=1`; владельца
  определяет сервер. Видео не предлагаются как изображения. Обычная Gallery
  продолжает использовать прежний порядок и фильтрацию без этого параметра.
- **Загрузить локально**: существующая форма и `gallery.php?action=upload_do`,
  `storage_provider=local`. Квоты, форматы, права и модерация проверяются Gallery.
- **Внешний хостинг**: та же форма Gallery с доступными пользователю провайдерами.
  ImgBB использует общий `upload_do` и существующий серверный провайдер. Вкладка
  скрывается, если нет доступных внешних провайдеров. Postimages не добавляется
  фиктивно: он появится только после регистрации готового провайдера в Gallery.

«Галерея» открывает вкладку «Мои изображения», «Изображение» — URL. После выбора
или успешной загрузки изображение вставляется и окно закрывается. Следующее
открытие использует тот же редактор и runtime. Ошибки загрузки показываются
внутри окна; загрузка защищена от повторного submit до завершения запроса.
При отключённой Gallery или отсутствии доступа её кнопка скрыта, инструмент
«Изображение» сохраняет отдельный лёгкий URL-режим с сообщением о недоступности
Gallery, без запросов к её runtime и обработчикам.

В сохранённом ACP layout кнопка Gallery восстанавливается рядом с `image`;
если `image` в layout отсутствует, Gallery добавляется один раз. Старый cmd
`af_gallery_picker` нормализуется к `af_gallery`. Иконки обеих команд — SVG.
Нативный hook Gallery не дописывает свою кнопку в SCEditor, принадлежащий AE.

## Вставка и жизненный цикл

Лёгкий адаптер `assets/bbcodes/media/media.js` хранит ссылку на конкретный
экземпляр редактора, выделение textarea либо DOM Range WYSIWYG. После выбора
восстанавливает курсор; в Source вставляет BBCode, в WYSIWYG использует штатный
`SCEditor.insert()` и существующий BBCode-конвертер. Серверный парсер не менялся.
Отмена возвращает фокус. При уничтожении редактора его активный медиапикер
закрывается, а запоздалый результат загрузки не вставляется в другой экземпляр.

Динамические редакторы получают команды через существующий MutationObserver
и реестр AdvancedEditor. Дополнительной инициализации редактора, клонирования
textarea или отдельного uploader в AdvancedEditor нет.

Gallery JS/CSS не включаются на страницы сообщений только из-за наличия редактора.
Они загружаются по первому открытию инструмента, с общей Promise и повтором после
сетевой ошибки. Обе кнопки используют одну загрузку. Для обычной Gallery и явных
потребителей оформления/аватаров существующая доставка ресурсов сохраняется.
Параметры `mediaTool`, `tab`, `onClose` и метод `AF_GalleryPicker.close()` добавлены
к существующему API; прежние `purpose`, avatar proxy и контракт сохранения не менялись.

Все URL ресурсов версионируются по содержимому. Ключи ImgBB и служебные URL
провайдеров в конфигурацию редактора не передаются. Внесённые изменения не требуют
новой схемы БД; после установки файлов нужно обновить страницу редактора.

## Проверки

`tests/editor_media_browser.cjs` использует реальный PHP/SQL fixture Gallery,
AdvancedEditor и официальный SCEditor из MyBB 1.8.40. Подменяется только транспорт
ImgBB и отображение внешних изображений; загрузка идёт через настоящий uploader.

Проверены:

- отсутствие Gallery runtime до клика и однократная загрузка после него;
- SVG-кнопка Gallery и один тулбар после Source/WYSIWYG-переключений;
- курсор Source с Unicode и фактическая DOM Range вставка в WYSIWYG;
- URL, собственные изображения, ImgBB и локальная загрузка;
- inline-ошибка неверного файла, возврат фокуса, мобильная ширина;
- Quick Reply, New Thread, New Reply, Edit Post;
- динамический Quick Edit, его удаление при открытом окне и отсутствие вставки
  в оставшийся Quick Reply;
- скрытая кнопка и URL fallback при отключённой Gallery.

Дополнительно пройдены существующие HTTP-регрессии ImgBB/URL/прав/CSRF/аватаров,
браузерный тест ImgBB, серверная проверка аватаров, runtime-тесты обоих аватаров
и подписи, проверки путей ресурсов и редактора подписи. Реальный внешний аккаунт
ImgBB не использовался.

Для повторения нужны отдельная MariaDB `gallery_test`, PHP с mysqli/cURL/Fileinfo,
`tests/gallery_imgbb_fixture.php --init` и HTTP-router этого fixture на 8101.
Для компиляции редактора fixture ожидает исходники форума под `MYBB_ROOT`
(`/tmp/ag-media-fixture`), отдельное временное дерево `uploads` и официальные
`jscripts` MyBB 1.8.40. Браузерный тест читает `work/mybb-media/jscripts`.
Рабочая БД и пользовательские файлы форума в тестах не используются.
