# AdvancedGallery 1.2.1: единый интерфейс источников

Форма страницы загрузки и модальное окно медиатеки используют одну форму и один
селектор: «Локальное хранилище», разрешённые внешние провайдеры (сейчас ImgBB),
«Добавить по URL». Недоступные пользователю провайдеры исключаются на сервере.
URL доступен только при включённой существующей настройке remote media и вне
контекстов оформления, которые ранее запрещали произвольные ссылки.
Postimages не добавлен: см. [результаты исследования](gallery-postimages-research.md).

Переключение источника скрывает и отключает ненужные поля, сохраняя элемент
`input[type=file]` и выбранный файл. Файл очищается после успешной загрузки.
У ImgBB сохраняется выбор загрузки файла или URL, если это разрешено в ACP.
Старый адрес `gallery.php?action=upload&tab=remote` выбирает URL в общем селекторе.

Все варианты отправляются через `upload_do`; значение `storage_provider=url`
делегирует существующему обработчику URL после POST/CSRF-проверки. Старый
`remote_add_do` сохранён для совместимости. Разрешённые домены URL, модерация,
владельцы, альбомы, локальные квоты и серверные проверки провайдеров сохранены.

## Списки и карточки

- Метки Local / ImgBB / URL определяются сохранённым типом и провайдером записи,
  а не доменом: вручную добавленная ссылка `i.ibb.co` остаётся источником URL.
- Фильтры доступны в «Загружено мной», внутри альбома и в модальной медиатеке.
  Фильтрация выполняется SQL-условием в дополнение к существующим ограничениям
  владельца, доступности альбома и статуса публикации. Общая страница альбомов
  сохраняет структуру; фильтрация изображений применяется внутри альбомов.
- Фильтр сохраняется при пагинации списка, смене сортировки альбома и переключении
  альбомов модального окна. Неизвестное значение фильтра игнорируется.
- В просмотре доступны открытие оригинала, копирование прямого URL и BBCode,
  выбор для редактора и удаление при существующем разрешении. Для локального
  изображения прямая ссылка указывает на оригинал, а не уменьшенное превью.
- Действие редактора вставляет BBCode в доступный `MyBBEditor` окна-источника
  того же origin. Если такого окна нет, копирует BBCode и сообщает о необходимости
  вставить его вручную. Доступ к другому origin не запрашивается.
- Внешняя карточка явно сообщает, что файл находится на внешнем сайте. Удаляется
  запись Gallery; прежнее сообщение об отсутствии удаления с хостинга сохранено.

## Обновление и проверка

Обновить файлы и реактивировать AdvancedGallery штатным механизмом ACP, чтобы
обновились базовые шаблоны. Реактивация сохраняет настройки и данные.
JS использует существующее версионирование по хешу содержимого. Если тема имеет
собственные переопределения шаблонов Gallery, соответствующие изменения нужно
перенести в них обычным механизмом обновления шаблонов.

Проверено на изолированной MariaDB и PHP 8.2; внешняя отправка ImgBB заменена
тестовым транспортом, реальные аккаунты не использовались:

- `gallery_imgbb_browser.cjs`: одна форма, сохранение файла между Local/ImgBB/URL,
  AJAX-загрузка, живые фильтры, исходная ссылка, копирование URL/BBCode/для редактора,
  выбор аватара, отсутствие ключей в клиенте.
- `gallery_imgbb_http_regression.py`: загрузки и ошибки, URL через общий обработчик,
  источник сохранённой записи, изоляция UID при фильтрации, CSRF, аватары, модерация,
  перенос и удаление, неизменность локальной квоты.
- `gallery_sources_regression.php`: классификация источника, скрытие недоступных
  провайдеров, отсутствие Postimages, allowlist фильтра и сохранение сортировки.
- Существующие проверки безопасности ImgBB, серверных аватаров и runtime-интеграции
  редактора/обоих аватаров.
