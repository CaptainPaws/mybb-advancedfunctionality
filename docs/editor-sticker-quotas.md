# AdvancedEditor: пользовательские стикеры и квоты

В ACP AdvancedEditor → «Стикеры» добавлена секция «Пользовательские стикеры»:

- Максимальный локальный файл: по умолчанию 2 МБ.
- Общая локальная квота: по умолчанию 20 МБ на пользователя; 0 отключает лимит.
- Исключение администраторов и модераторов из суммарной квоты: включено.
- Добавление внешних стикеров по URL: включено.

Единицы соответствуют существующему интерфейсу: 1 МБ = 1 048 576 байт.
Настройки сохраняются в прежнем файле
`inc/plugins/advancedfunctionality/cache/advancededitor_stikers.json`.
Сохранение размеров отображения сохраняет квоты, а сохранение квот — размеры.
Отсутствующие параметры получают значения по умолчанию при чтении; повторная
инициализация и активация не перезаписывают существующий файл. Запись JSON
выполняется через временный файл и атомарное переименование.

## Хранилище и учёт

Папка не меняется:
`inc/plugins/advancedfunctionality/addons/advancededitor/assets/stikers/`.
Пользовательские файлы по-прежнему сохраняются в `stikers<UID>/`.
AdvancedGallery в обработке стикеров не участвует.

Для учёта используются существующие `uid` и `is_user_sticker=1`.
Размер определяется через `filesize()` по реально существующим файлам,
канонический путь которых находится внутри папки стикеров. Одинаковый
канонический путь учитывается один раз. Внешняя запись имеет пустой `path`;
системные записи `is_user_sticker=0` не учитываются даже при ненулевом UID.
Рекурсивного обхода общей папки нет: проверяются только пути записей владельца.
Существующие пользовательские файлы учитываются сразу, в том числе файлы,
которые превышают новый максимальный размер одного файла.

Схема уже хранит владельца. Для старой таблицы без `uid` предусмотрено только
добавление столбца и индекса; существующим записям задаётся `uid=0`. Миграция
повторно проверяет столбец под блокировкой БД. Владельцы не выводятся из имён
папок или URL и автоматически не назначаются. Нераспределённые записи и файлы
сохраняются; они не списываются с произвольно выбранного пользователя.
Файлы без записей БД также не импортируются и не получают предполагаемых владельцев.

## Серверные ограничения

Локальная загрузка проверяет ошибку PHP upload, `is_uploaded_file()`, фактический
размер, разрешённое расширение и совпадение MIME по Fileinfo и `getimagesize()`.
Поддерживаются прежние PNG, GIF, JPEG и WebP, без конвертации оригинала.
При отсутствии Fileinfo загрузка отклоняется. Ограничения PHP/web-сервера
продолжают действовать независимо от настроек аддона.

Проверка общего остатка и числа записей, выбор имени, перенос файла и сохранение
записи выполняются под MySQL/MariaDB `GET_LOCK` для владельца. Удаление использует
ту же блокировку. Это работает с прежними MyISAM-таблицами и не зависит от
локального `flock`. Недоступность блокировки запрещает запись. При ошибке
регистрации удаляется только новый файл текущей операции; старые файлы не затрагиваются.

Административные права и права супермодератора проверяются по серверным
разрешениям MyBB и основной/дополнительным группам; форумные модераторы — через
`is_moderator(0, '', UID)`. Клиентские флаги сотрудников не используются.
Исключение отменяет суммарную квоту, но не максимальный размер одного файла.
Прежний лимит 60 пользовательских записей сохранён. Лимит ACP-загрузки системного
стикера остаётся прежним — 5 МБ; системные файлы не перемещаются и не пересчитываются
в пользовательскую квоту.

Если квота уже превышена, существующие стикеры остаются в каталоге.
Новые локальные загрузки блокируются до освобождения места. При удалении
локального файла ошибка `unlink()` не скрывается удалением его записи.

## URL и интерфейс

В «Свои стикеры» добавлены расход, лимит и остаток. После загрузки или удаления
данные перечитываются без перезагрузки страницы, активная вкладка сохраняется.
При полном хранилище локальный выбор файла отключён; серверная проверка действует
независимо от UI. Для пользователей без квоты выводится фактический расход и
«Без ограничений».

URL добавляется в том же окне, если разрешён в ACP. Новые ссылки принимаются только по HTTPS без
учётных данных, в пределах существующей длины поля БД. PHP проверяет ограниченный
префикс изображения в памяти с защитой от SSRF; постоянная копия не создаётся.
Подробности: [внешние стикеры](editor-external-stickers.md). Ссылка не расходует локальный объём.
Прямая ссылка должна вести на изображение; её доступность зависит от внешнего сайта.
Отключение добавления URL сохраняет уже существующие записи. Удаление такой
записи удаляет только запись каталога, а не файл на внешнем сайте.

## Проверки

Изолированная MariaDB, PHP 8.2 с четырьмя HTTP worker и Chromium:

- `tests/editor_sticker_fixture.php --init`: старые файлы, исключение системных,
  миграция отсутствующего UID без назначения владельцев, сохранение размеров и квоты.
- `tests/editor_sticker_http_regression.py`: реальные multipart-загрузки, неверный
  формат, несовпадение MIME и расширения, размер файла, CSRF/UID, две конкурентные
  загрузки, поддельные флаги сотрудников, основные/дополнительные группы и
  модераторский механизм, URL, удаление, превышение квоты и 0 без ограничения.
- `tests/editor_sticker_browser.cjs`: реальная модалка, расход/остаток после загрузки
  и удаления, нулевой расход URL, сохранение вкладки, сотрудники и мобильная ширина.
- Пройдены существующие проверки `advancededitor_installed_asset_paths_regression.php`
  и `signature_editor_regression.php`.

`advancededitor_feature_lazy_regression.php` падает на проверке иконки Tables:
«Tables must not carry the Tabs menu Font Awesome icon». Та же ошибка воспроизведена
на отдельной копии исходного main (`e785974d`) без изменений этой задачи.
Проверка не относится к квотам стикеров; её результат не заявлен как успешный.

Тестовый HTTP-сервер использует только БД `gallery_test` и дерево
`/tmp/ae-sticker-fixture`, не рабочую БД и папку форума. Для повторения требуется
отдельный PHP-контейнер с mysqli/Fileinfo, MariaDB и общим bind mount этого
временного дерева между CLI-инициализацией и HTTP worker.

## Исправление выбора источника (1.1.4)

В «Свои стикеры» явно выбирается «По внешнему URL» или «С устройства».
Если URL разрешён, поле ссылки видно по умолчанию; выбор файла открывается
только для источника «С устройства». Сохранённый выбор сохраняется при обновлении
списка. При отключённом URL остаётся локальная загрузка.

JS стикеров в реестре ленивых ресурсов теперь получает параметр с хешем содержимого:
это обновляет адрес ресурса при изменении файла, даже если при развёртывании
сохраняется его mtime. На показанном пользователем скриншоте отсутствовали также
индикатор квоты и URL-форма версии 1.1.3; точная версия установленного на сайте
файла без доступа к серверу не проверялась. После установки новых PHP и JS нужно
обновить страницу форума, чтобы получить новый адрес ресурса.
