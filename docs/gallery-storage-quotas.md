# Локальные квоты AdvancedGallery

В ACP → AdvancedFunctionality → AdvancedGallery доступны статистика хранилища и ссылка на настройки.

- `af_advancedgallery_max_storage_mb`: квота локального хранилища пользователя в МБ (1 МБ = 1 048 576 байт). Старое значение сохраняется. `0` отключает объёмную квоту.
- `af_advancedgallery_upload_max_mb`: существующий максимальный размер одного локального файла, действует для всех. Существующая семантика неположительного значения сохранена: используется 10 МБ.
- `af_advancedgallery_storage_exempt_staff`: по умолчанию `1`. Освобождает от объёмной квоты администраторов MyBB (`cancp`), супермодераторов (`issupermod`), модераторов MyBB и участников групп модерации Gallery. Учитываются основная и дополнительные группы, права определяет сервер. Право загрузки это исключение не предоставляет.

Квота и пользовательский виджет суммируют `filesize` локальных оригиналов владельца, включая approved/pending/rejected, системные альбомы, аватары, подписи и файлы без альбома. Оригинал учитывается один раз независимо от количества связей с альбомами. Внешние изображения и их виртуальный размер исключены. Миниатюры не входят в квоту оригиналов; заполнение файлового тома учитывает все физические данные на нём.

При заполненной квоте существующие изображения доступны. Сервер проверяет остаток под существующим MySQL owner-lock от проверки до записи нового медиа. При удалении исходника его размер освобождается; сохранённые для оформления файлы по-прежнему защищены от удаления.

На страницах Gallery пользователь видит использованный объём, лимит, остаток и progress bar. Для отсутствующего лимита и освобождённых сотрудников показывается «Без ограничений». Загрузка в Picker и загрузка/удаление на странице обновляют виджет через AJAX; обычный POST остаётся fallback без JavaScript. При частичном массовом удалении сервер возвращает фактическое число удалённых файлов, виджет обновляется; список можно обновить отдельно.

ACP считает локальные файлы, владельцев, объём оригиналов и внешние изображения. Системная разбивка использует индексированные связи с `EXISTS`, поэтому не дублирует файлы, состоящие в нескольких альбомах. «Остальные» включает обычные альбомы и файлы без альбомов. Показатели тома берутся по фактическому `realpath(uploadspath/af_gallery)`. Ожидаемая точка монтирования проверяется через `/proc/self/mountinfo`; по умолчанию это сам `uploadspath`. Для иной схемы размещения её нужно явно указать в настройке `storage_mount_path`. Необязательная `storage_mount_device` позволяет проверить и устройство (например `/dev/sda1`). При отсутствии ожидаемого подключения статистика родительского/корневого диска не подставляется.

GNU `stat -f` считывает `statfs`: полную ёмкость, все свободные блоки и доступные блоки. Занятость равна `(f_blocks − f_bfree) × f_frsize`, доступность — `f_bavail × f_frsize`, свободный резерв — `(f_bfree − f_bavail) × f_frsize`. Progress bar использует только фактически занятые блоки. При недоступности точных счётчиков допускаются отдельно подтверждённые ёмкость и доступность из PHP, без вычисления занятого места или процента. Рекурсивного сканирования, root, sudo и изменения файловой системы нет. Подробности: [gallery-storage-filesystem.md](gallery-storage-filesystem.md).

Повторное включение через AF вызывает install; теперь `af_ag_ensure_setting` обновляет метаданные без изменения сохранённого `value`. Install/activate/upgrade добавляют недостающие настройки, синхронизируют языковые подписи manifest и пересобирают/перечитывают settings после завершения добавлений. Deactivate не удаляет данные. Явный uninstall сохраняет прежнюю семантику удаления таблиц/настроек аддона; он не нужен для обновления и не выполняется миграцией.

Для обновления достаточно загрузить исходники и реактивировать аддон. Схема медиа для квот не меняется; существующие аддитивные миграции системных альбомов сохранены.

## Проверки

Только на изолированной БД `gallery_test`:

```sh
AG_TEST_DB_HOST=af-gallery-test-db AG_STORAGE_WIDGET_OUTPUT=work/storage-widget.html php tests/gallery_media_api_integration.php --storage
node tests/gallery_storage_runtime_regression.cjs
php tests/gallery_media_api_integration.php
# При запущенном PHP fixture-сервере на 127.0.0.1:8099:
python3 tests/gallery_storage_http_regression.py
```

Нужны PHP с mysqli, MariaDB/MySQL и Playwright/Chromium. Первая проверка пересоздаёт fixture-таблицы `test_*`, проверяет серверные права, размер одного файла, квоту, конкуренцию двух соединений, удаление, ACP-контроллер, путь диска и сохранение настроек/альбомов/метаданных при реактивации. Затем проверяет явный uninstall на fixture. Браузерная проверка использует настоящий PHP-виджет и моделирует AJAX-ответы: заполнение, отказ, удаление, отсутствие лимита и отсутствие перезагрузок. HTTP-проверка отправляет реальные multipart-запросы: отказ по квоте, загрузка сотрудника сверх квоты, ограничение размера файла для сотрудника, статистика и освобождение места после удаления. Дополнительно запускаются текущие регрессии редактора аватаров и Gallery Picker.
