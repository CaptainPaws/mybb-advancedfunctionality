# APStudio / ATF: базовое отображение и масштаб аватаров

Причины: основной `<img>` позиционировался через `top/left:50%` и `transform:translate(-50%,-50%)`, тогда как компилятор добавлял независимый CSS `scale`. Масштабирование изменяло результат центрирующего преобразования. Дополнительный аватар имел конфликтующие поздние правила `width:auto`, `height:auto`, `object-fit:contain`; при масштабе компилятор включал `overflow:hidden` на внешнем контейнере с Gothic-рамкой. Ползунок без значения показывал минимум диапазона 25%, хотя базовый рендер использовал 100%. JavaScript не выполнял дополнительного масштабирования: он сохранял параметры и запрашивал CSS.

Общие правила ATF и общий компилятор AA теперь используют `--aa-avatar-scale`, `--aa-avatar-fit`, `--aa-avatar-position` на самом изображении. Основной аватар занимает круглую внутреннюю область от её начала (без translate); масштабируется вокруг указанного положения, по умолчанию центра. Внешние декоративные элементы остаются отдельными узлами.

Дополнительный аватар получил внутреннюю `.atf-post__secondary-avatar-media`, которая обрезает только медиа и наследует форму внутренней области. Его внешняя рамка, отступы и естественное соотношение сторон не меняются при зуме. Высота прямоугольной рамки по-прежнему определяется исходной пропорцией изображения: фиксированная новая форма/высота не вводится. AJAX-обновление маски и её примерка сохраняют этот внутренний узел вместе с внешней рамкой.

100% означает базовое заполнение. `cover` использует минимум 100%, чтобы старые значения 25–99 не открывали пустые края; данные в БД не переписываются. Явные `contain`/`none` сохраняют возможность меньшего масштаба. Старый `fill` остаётся допустим при чтении пресетов, но для аватаров отображается как `cover`, без растяжения пропорций. В UI `fill` для аватаров не предлагается. Положение не сбрасывается при смене масштаба. Для плашки механизм не изменён.

Проверки ограничены синтаксисом изменённого JS/PHP и существующим тестом настроек/компилятора с адресными проверками scale/fit/position, сохранности JSON-значений, отсутствия обрезки внешней рамки и defaults UI. Полномасштабные и визуальные браузерные проверки не запускались по просьбе заказчика. PHP-стенд: 8.2; целевой PHP 8.5 отдельно не запускался.
