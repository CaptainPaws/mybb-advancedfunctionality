# Выбор основного аватара из Advanced Gallery

Страница: `usercp.php?action=avatar`. MyBB 1.8.40, проверка на PHP 8.5.

В существующую форму добавлен блок «Выбрать из моей галереи»: открытие штатного Picker, миниатюра оригинала, подтверждение и отмена. Хук `usercp_avatar_end` выполняется с приоритетом 1100, после сборки UserCP в ATF (1000). Изменяется только request-local кэш шаблона; ядро MyBB и шаблоны ATF/APUI не правятся. Блок работает и со стандартным шаблоном MyBB.

Picker использует отдельный purpose `account_avatar`, не связанный с `appearance_avatars` и дополнительным аватаром персонажа. Сразу показаны все собственные одобренные локальные изображения. Запросы ограничены текущим владельцем; чужие приватные альбомы и media ID не принимаются. Список форматов фильтруется через штатный cache attachtypes, avatarfile и группы пользователя. Пользователь с правом аватаров может выбрать ранее загруженный файл даже без текущего права загрузки в Gallery. В таком случае загрузка в модалке скрыта, а её серверный обработчик продолжает запрещать загрузку.

## Штатное сохранение MyBB

`upload_avatar()` в MyBB 1.8.40 проверяет `is_uploaded_file()`. Поэтому безопасная интеграция передаёт оригинальные байты Gallery в существующее поле `avatarupload` через File/DataTransfer и отправляет существующую multipart-форму с `action=do_avatar`. Пользователю не нужно повторно выбирать файл на устройстве. Технически браузер получает оригинал с форума и отправляет его штатной форме; серверная подмена пути или отдельный загрузчик не используются.

Перед штатным обработчиком хук проверяет CSRF, canusercp/canuploadavatars, владельца, одобрение, локальный тип, канонический путь внутри собственного каталога Gallery и MIME. SHA-256 полученного multipart-файла должен совпасть с оригиналом, определённым по серверному media ID; браузер не задаёт серверный путь. MIME/имя нормализуются по проверенному оригиналу.

Далее неизменённый MyBB выполняет upload_avatar(), проверяет размер, разрешённый MIME/группу, геометрию, политику уменьшения и выполняет сохранение. Только штатный обработчик UserCP обновляет `users.avatar`, `avatardimensions`, `avatartype`, добавляет dateline и удаляет прежние аватары. В коде Gallery нет записи полей пользователя. Поэтому профиль, постбит, AdvancedMenu и другие потребители основного аватара получают тот же штатный аватар; независимые пользовательские переопределения других плагинов не меняются.

Оригинал Gallery не изменяется; обычная копия аватара создаётся исключительно инфраструктурой MyBB. Новый purpose не закрепляет исходник навсегда через appearance_retained: после штатного копирования аватар не зависит от существования записи Gallery. Если пользователь загружает новый файл в Picker, применяется существующий загрузчик и служебный альбом Gallery.

## Форматы и GIF

Штатный upload_avatar() MyBB 1.8.40 не принимает WebP. Picker предлагает только поддержанные им JPG/PNG/GIF, дополнительно разрешённые настройками форума. Для GIF используется оригинал, не thumbnail и не canvas. GIF, превышающий maxavatardims, отклоняется с объяснением риска потери анимации при уменьшении средствами MyBB; даже статический GIF в этом случае отклоняется консервативно. GIF подходящего размера проходит без перекодирования. JPG/PNG при необходимости уменьшает штатная инфраструктура MyBB в рамках его настроек.

## Совместимость

Стандартная загрузка/удаление/URL не перехватываются, если не нажата отдельная кнопка подтверждения Gallery. При отключённой Gallery блок не вставляется. Отсутствие поддержки File/DataTransfer/requestSubmit отключает только кнопку Gallery с пояснением. Новых полей пользователей, системы хранения аватаров и зависимостей JS нет. Ресурсы Gallery подключаются существующим владельцем assets по маркеру UI, включая avatar/do_avatar в контекстных маршрутах.

## Проверки

- PHP 8.5: синтаксис изменённых PHP-файлов, gallery_avatar_regression.php.
- Отдельный настоящий multipart HTTP-запрос через оригинальную функцию upload_avatar() из тега mybb_1840: успешный GIF с одинаковым SHA-256 у оригинала и аватара; ошибки CSRF, владельца, прав, MIME, несовпадения байтов, лимита файла; стандартная загрузка при отключённой Gallery.
- Короткий локальный Chromium-сценарий: purpose Picker, выбор, отмена, передача неизменённых GIF-байтов в штатное поле и стандартная отправка формы.
- Существующий signature_gallery_runtime_regression.cjs дополнен проверкой открытия account_avatar; прежние purpose работают.
- git diff --check.

HTTP-проверка опциональна: запустить встроенный PHP-сервер с router `tests/gallery_avatar_regression.php` и переменной MYBB_UPLOAD_SOURCE, указывающей на неизменённый `inc/functions_upload.php` MyBB 1.8.40, затем `python tests/gallery_avatar_http_regression.py`. Все данные только в `/tmp/ag-avatar-regression/`; не запускать fixture на боевом форуме. Полный UserCP/профиль/постбит/AdvancedMenu на рабочем сайте облачными UI-тестами не проверялись.

## Файлы

В `inc/plugins/advancedfunctionality/addons/advancedgallery/`:

- `avatar.php` — новый адаптер формы и серверная проверка выбора.
- `advancedgallery.php` — хуки, контекст assets, ограничения Picker и обычное хранение новых исходников аватара.
- `media_api.php` — purpose, все собственные изображения по умолчанию, выбор без закрепления исходника.
- `assets/advancedgallery.js` — выбор/миниатюра/отмена и передача в стандартную форму.
- `templates/advancedgallery.html` — скрытие загрузки без права Gallery upload.
- `manifest.php` — маршруты avatar/do_avatar.

Проверки: `tests/gallery_avatar_regression.php`, `tests/gallery_avatar_http_regression.py`, `tests/gallery_avatar_runtime_regression.cjs`, `tests/signature_gallery_runtime_regression.cjs`.

После обновления исходников сбросить кэш статических ресурсов применяемым на форуме способом. Изменений схемы БД для этой интеграции нет.
