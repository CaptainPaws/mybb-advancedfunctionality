# AdvancedGallery: исследование Postimages

Дата проверки официальных источников: 18 октября 2026 года.

## Решение

Задача завершена техническим отчётом по предусмотренному в этапе B варианту.
Поддерживаемый механизм, удовлетворяющий требованиям общей формы Gallery и
подтверждённого результата загрузки, не установлен. Провайдер `postimages`,
пункт селектора, настройки и пустые системные альбомы не добавлены.
Локальная Gallery, ImgBB, права доступа и локальные квоты не изменены.

Это не утверждение, что интеграция с Postimages технически невозможна вообще.
Официальный форумный виджет существует, однако его опубликованные возможности
не дают требуемого документированного контракта для этой интеграции.

## Ответы на вопросы этапа A

## Как устроен официальный MyBB-плагин

Архив, на который ссылается официальная страница, содержит один PHP-файл
`image-upload/image_upload.php` (721 байт), версия плагина `1.0.3`.
Его единственный рабочий hook — `pre_output_page`. Перед `</head>` он вставляет:

```html
<script type='text/javascript' src='//mod.postimage.org/mybb.js' charset='utf-8'></script>
```

В PHP нет серверной отправки файлов, авторизации API, сохранения метаданных
или интеграции с медиакаталогом MyBB.

Исследованный `mybb.js`:

1. Находит текстовые поля и добавляет ссылку загрузки рядом с редактором.
2. `postimage.upload(areaid)` открывает окно
   `https://postimages.org/upload` с параметрами `mode`, `areaid`, `hash`,
   `pm`, `lang`, `code`, `forumurl`.
3. Обработчик `message` принимает только origin `https://postimages.org`,
   проверяет `e.source === postimage.windows[id].window`, затем передаёт
   `decodeURIComponent(e.data.message)` в `postimage.output`.
4. `postimage.output(i, res, co)` вставляет текст в `MyBBEditor.insert`,
   `MyBBEditor.insertText` или в значение textarea.
5. Скрипт также содержит drag-and-drop через Dropzone: внутренний `/json`,
   затем `/mod`, откуда приходит текст для редактора. Наличие этих маршрутов
   в официальном JS не делает их публичным API. Запросы загрузки к ним
   в ходе исследования не выполнялись.

Публичная документация описывает размер превью, язык и стили через
`postimage_customize()`. Эта функция настраивает оформление; документированного
callback с ID изображения, MIME, размером, размерами оригинала и проверяемым
подтверждением загрузки там нет.

## Почему адаптер не реализован

Замена `postimage.output` или чтение сгенерированного BBCode потребовали бы
зависимости от недокументированного поведения и формата текста. Окно загрузки
Postimages сохраняет собственный интерфейс. Перенос обнаруженных `/json` и
`/mod` в общую форму означал бы использование внутреннего протокола без
подтверждённого разрешения сервиса.

Даже корректная проверка `postMessage` в браузере не удостоверяет для PHP,
что присланные клиентом URL и метаданные действительно получены при загрузке:
пользователь может отправить POST напрямую. Проверка домена URL подтверждает
только допустимый хост, а не загрузку через Gallery или владение изображением.
В исследованных материалах не найден серверный callback, подписанный результат
или API проверки операции, позволяющий выполнить требование о сохранении
только подтверждённых результатов интеграции.

В [условиях использования](https://postimages.org/terms) написано:

> Automatic or programmatic uploads are not allowed. If you need image storage
> for your app, please use Amazon S3 or Google Cloud Storage. Violators may be
> hunted down and banned.

Этот запрет не следует трактовать как запрет самого официального виджета.
Однако он не позволяет считать собственный серверный uploader разрешённым
только потому, что его запросы можно воспроизвести по исходникам.

## Что позволит возобновить реализацию

Нужны официальная документация или согласованный с Postimages контракт,
разрешающий собственную форму загрузки и описывающий:

- авторизацию, лимиты, формат ошибок и стабильный способ отправки файла;
- прямой URL оригинала и необходимые метаданные;
- подтверждение операции, которое может проверить сервер Gallery;
- правила использования виджета без отдельной кнопки редактора, если выбран
  именно виджет, а не API.

Официальная страница предлагает помощь с интеграцией через
[контактную форму](https://postimages.org/contact). Сообщения сервису не отправлялись.
После появления такого контракта можно использовать существующий реестр
`AG_StorageProvider`, приватные метаданные внешних изображений и системный
альбом `provider_postimages`; переработка локального uploader не требуется.
Импорт полной истории и удаление с хостинга также потребуют отдельных
подтверждённых возможностей сервиса.

исполняемый код и схема БД не менялись.
