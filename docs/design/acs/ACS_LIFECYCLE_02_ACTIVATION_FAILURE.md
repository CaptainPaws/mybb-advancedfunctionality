# ACS-LIFECYCLE-02 — Отказ при включении ACS

## Подтверждённый дефект

В обработчике включения AF результат `af_advancedcombatsystem_is_installed()` использовался для решения о запуске установки. Метод возвращал `false` как при отсутствии схемы, так и при любом отказе её проверки. В результате даже установленная схема с ошибкой чтения или проверки попадала в маршрут `install → Migrations::run()`, а отказ помечался как `install`. После этого lifecycle сводил неизвестные исключения к `ACS_DATABASE_ERROR`, а `Repository::statement()` оборачивал реальные ошибки mysqli тем же общим текстом. Это объясняет ошибочную метку операции и потерю сведений, необходимых для восстановления.

Сравнение `main` до и после PR #1138 и #1139 показало, что оба PR не меняли lifecycle, Repository, MigrationManager или декларации миграций. На основании старой записи невозможно восстановить, какой запрос или проверка дали сбой на warprift.ru. В частности, нет подтверждения, что выполнялась запись checksum-аудита. Для определения отказа на сервере нужна новая запись диагностики.

## Исправление

- Автоматическая установка запускается только по явному `ACS_NOT_INSTALLED`, когда успешно прочитанные метаданные не содержат объектов ACS. Неудачное чтение, несовместимый журнал и незавершённая миграция переходят в обычную активацию для точной диагностики без DDL. Для незавершённой миграции остаётся штатная команда обновления в ACP.
- Repository отклоняет подключение без выбранной базы, чтобы пустая выдача метаданных в этом случае не считалась отсутствием ACS. Для сбоев mysqli сохраняется числовой код драйвера, в том числе когда mysqli возвращает `false`. MigrationManager преобразует известные причины в машинные коды, например `ACS_DB_PERMISSION_DENIED`, `ACS_DB_COLUMN_UNKNOWN` и `ACS_DB_TABLE_UNAVAILABLE`. Для остальных доступных кодов драйвера используется `ACS_DB_ERRNO_<номер>`. Неизвестные ошибки приложения получают `ACS_LIFECYCLE_UNEXPECTED` и краткую запись во внутреннем журнале.
- Активация по-прежнему выполняет `activate → status → requireReady → recordChecksumDifferences` под блокировкой обслуживания. Ошибка до `READY` останавливает включение. Если схема уже `READY`, но отказало чтение или добавление записи checksum-аудита, ACP показывает соответствующую фазу и объект `diagnostics`.
- AF показывает операцию, фазу, машинный код, статус схемы, ID ошибки и, когда они достоверно известны, миграцию и объект. До получения результата проверки статус отображается как `NOT_CHECKED`. В цепочку передачи и журнал попадают только безопасные значения. SQL, параметры соединения, исходный текст исключения и содержимое игровых записей не передаются.

## Состояние миграций и данных

Требуемая версия остаётся `029_statistics`. Изменений DDL, контрольных сумм и журнала миграций нет. Активация исправной схемы сохраняет исторические checksum. Если они отличаются от развёрнутых файлов, существующий механизм по-прежнему записывает одну диагностическую запись на набор расхождений после проверки структуры. Проверки миграций и физической схемы остаются строгими. Игровые таблицы, операции, снимки, сущности и резервы Inventory остаются на месте.

## Статические проверки

`php -l` для изменённых PHP-файлов на PHP CLI 8.4.27, `git diff --check`, сверка маршрутов и состава изменений. Проверка установленного форума — **NOT_VERIFIED**.

## Ручная проверка

1. Развернуть изменённые файлы и включить ACS из списка аддонов AF на установленной схеме. При успехе проверить статус `READY`, доступность существующих сессий и историю операций.
2. Если включение снова отклонено, сохранить строку ACP с `operation: activate` и `error_id`. Сверить фазу и код с разделом диагностики ACS. Фазы `checksum_diagnostic_lookup` и `checksum_diagnostic_insert` при `READY` локализуют сбой после проверки структуры.
3. На отдельной копии проверить отказ на схеме с уже известным несоответствием. Настройка включения должна остаться выключенной, а ACP должен указать конкретный код проверки и известную миграцию или объект.
4. Сверить сохранённые checksum и наличие существующих сессий, столкновений, сущностей, истории и резервов после штатной попытки включения.
