# ATF-ACS-04 — Обратимый режим эпизода

## Хранилище и совместимость

AdvancedThreadFields создаёт InnoDB-таблицу `af_atf_acs_episode_modes` при установке, активации или сохранении разрешающей Group. В ней хранятся TID, явный режим, версия, автор изменения и время. Сессии, история и миграции ACS сохраняются. Для темы без явного режима наличие сессии или подтверждённого намерения из #1095 означает боевой режим. При отсутствии обоих источников обычная ATF-тема имеет обычный режим. Группа определяет возможность нового включения ACS без сессии. Уже созданная сессия сохраняется при изменении группы.

## Переходы

Переключатель доступен только в форме первого поста. Сохраняются выбранный режим и версия формы при предпросмотре и ошибках валидации. Форма показывает состояние столкновения отдельно. Переход записывается в `editpost_do_editpost_end` после сохранения MyBB. ACS повторяет проверку CSRF, native-доступа, права редактирования, PID первого поста и текущих сохранённых прав owner/GM. Для темы без сессии проверяется право создания ACS.

ACS доказывает обратимость по состоянию столкновений и наличию раундов, по журналу операций и событий, по данным боевых результатов, наград, бросков, публикаций и по существующему запросу обязательств. Допускаются только завершённые внутренние операции из явного списка безопасной подготовки. Стартовавшее или завершённое столкновение, неизвестное состояние, неподтверждённая операция, расход ресурсов, долговременное обязательство, закрытая сессия или несколько сессий блокируют переход. В подготовке без этих признаков можно сменить режим. Форма сообщает причину и позволяет сохранить обычные поля.

ACS выполняет изменение под тем же lock, что и команды сессии. Версия защищает от устаревшего POST, а повтор подтверждённого выбора не создаёт второй записи. При включении без сессии режим сохраняется первым, затем вызывается `SessionService::command('create')` с прежним ключом ATF. Неизвестный ответ оставляет восстанавливаемый боевой режим без подтверждённой сессии. Мастер использует тот же ключ. Поздний вызов создания блокируется, если режим уже переключён в обычный. При повторном включении с существующей сессией сохраняются прежний session_id, состав и подготовка.

## Запрет выполнения

`Repository::lockSession()` читает сохранённый режим на writer под общей блокировкой и отклоняет команды в явно обычной теме. Через этот путь проходят штатный запуск первого раунда, ambush, подготовленный запуск, черновики, запечатывание, публикационная запись и боевые результаты. Общее создание сессии проверяет режим отдельно, когда блокировать ещё нечего. Обычный режим скрывает GM-панель темы. ACP показывает тип эпизода отдельно от состояния сессии. Отключение не закрывает сессию, не архивирует её и не запускает механику.

## Проверки и ограничения

Проверка `git diff --check` прошла. PHP CLI недоступен. JS не менялся, автоматические тесты не создавались и не запускались. До применения ATF-схемы новые переключения блокируются. Старые сессии продолжают использовать обычный lifecycle ACS. Фактическое переключение, повторный запуск с прежним session_id и гонка с запуском боя требуют ручной приёмки владельцем.
