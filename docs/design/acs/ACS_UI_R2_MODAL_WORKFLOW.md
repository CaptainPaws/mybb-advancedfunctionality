# ACS-UI-R2 — Панель боя и модальные инструменты

## Интерфейс темы

`af-acs-combat-bar` выводится в слоте R1 перед редактором быстрого ответа. Панель показывает название, текущее состояние, номер существующего раунда, HP своей группы и AP при наличии разрешённых данных. Сведения о других участниках берутся из прежней проекции аудитории. GM получает вход в управление, игрок с правом подготовки хода — в Builder, observer видит только сведения. Выбор среди нескольких сессий сохраняет серверные проверки R1.

Модалка использует штатный хост ATF и нативный `dialog`. После закрытия фокус возвращается к кнопке. В обычной боевой теме загружается компактный launcher. Стили GM, Builder и скрипт засады подключаются по мере открытия соответствующих инструментов. После закрытия Builder снимает глобальные слушатели, отменяет чтения и очищает таймеры. Тёмные поверхности и состояния контролов используют токены ATF.

## Мастер и команды

- `misc.php?action=acs_modal` возвращает HTML текущего представления в JSON. Мастер проходит этапы «Сессия», «Столкновение», «Участники», «Проверка», «Предпросмотр», «Запуск». Управление раундами и состоянием остаётся доступным в модалке.
- Режим темы, привязка TID/SID и роль проверяются по тому же пути, что и для прямых ссылок. GET читает сохранённое состояние. POST проверяет CSRF, ключ идемпотентности и привязку формы, затем передаёт команду действующим сервисам, которые проверяют версии. Проверка готовности вызывается явной командой.
- При отказе форма остаётся на экране. «Обновить шаг» перечитывает версии и восстанавливает доступные редактируемые поля соответствующей формы. Подтверждение последствий требуется заново. При неизвестном исходе повтор возможен только вручную с прежним запросом. Запрос сохраняется до закрытия страницы, в том числе при закрытии и повторном открытии модалки.
- После подтверждённой команды обновляются представление инструмента и данные панели. AdvancedEditor и список сообщений остаются в существующем DOM. Builder использует действующие выбор способностей и целей, черновики, сводку и подтверждение. Переход из Builder в редактор по-прежнему выполняется явной командой пользователя через существующий маршрут публикации. Capability gate публикации сохраняется.
- Прямые ссылки `showthread.php?...&acs_setup=1`, `gm_step=N`, `acs_builder=SID` и `misc.php?action=acs_sessions` остаются доступны. Серверные формы GM работают по прямой ссылке без JS. Интерактивный Builder сохраняет прежнее требование JavaScript.

## Изменённые файлы

- Вход и проекция панели в `advancedcombatsystem.php`, `ModalWorkflow.php`, `ThreadComponents.php`, `ThreadPanel.php` и `ThreadPanelQuery.php`.
- Представления инструментов в `Encounters.php`, `GmPanel.php`, `BuilderController.php`, `Ambush.php` и `RuntimeAssets.php`.
- Клиентское поведение и оформление в `thread-panel.js`, `runtime.js`, `builder.js`, `ambush.js`, `presentation.css`, `modal-gm.css` и `builder.css`.

## Проверки

`git diff --check` и `node --check` для четырёх изменённых JS-файлов прошли. PHP CLI недоступен. Автоматические и интеграционные тесты не создавались и не запускались.

### Ручная приёмка

1. В боевой теме открыть мастер из тулбара и панели. Сверить отсутствие изменений после GET, создать сессию и столкновение и проверить TID/SID в записи.
2. Пройти все шесть этапов. Проверить регистрацию, готовность, предпросмотр, явный запуск и управление раундом. Сверить содержимое панели после каждой подтверждённой команды.
3. В двух вкладках вызвать конфликт версии. Проверить текст ошибки, сохранение заполненных полей, явное обновление шага и повторную необходимость подтверждения. Проверить неизвестный исход команды и ручной повтор с прежним ключом.
4. Сверить выдачу GM, игроку и observer, включая прямые запросы с чужими ID и обычную тему. Открыть и закрыть Builder несколько раз, проверить черновик, сводку и переход в редактор при действующем допуске.
5. На телефоне проверить внутреннюю прокрутку, фокус после закрытия и сохранность текста в быстром ответе. С отключённым JS проверить прямые URL и отправку формы GM.
