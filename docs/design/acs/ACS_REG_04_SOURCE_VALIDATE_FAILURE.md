# ACS-REG-04 — Проверка источника персонажа

## Причина сбоя обработки

Для обращения `6cceeb7e4286bc6dd5ed85e3fff21b49` точное историческое исключение подтвердить не удалось. Производственный журнал недоступен в рабочем окружении, а прежняя запись ACS для этой ветки сохраняла только категорию, `session_command` и `validation`. Из такого ID нельзя восстановить класс или место исходного исключения.

По коду подтверждён дефект обработки. `AF_ACS_Repository::integer()` выбрасывает `InvalidArgumentException('ACS_INVALID_INTEGER')` или `InvalidArgumentException('ACS_INTEGER_RANGE')`, а `AF_ACS_Repository::json()` при превышении лимита выбрасывает `InvalidArgumentException('ACS_JSON_TOO_LARGE')`. Эти исключения обходили обработчик `RuntimeException` в `EntityService::validate()`. Исключения инвентаря `RuntimeException('INV_SOURCE_CHANGED')`, `INV_VERSION_CONFLICT` и `INV_INCOMPLETE_SNAPSHOT` также пробрасывались, поскольку отсутствовали в списке ожидаемых исходов. Верхняя ветка `EncountersPage` классифицировала исключение как сбой команды и могла включать предупреждение о неизвестном исходе записи. Эти точки установлены статически. Связь конкретного исключения с указанным обращением не установлена.

## Исправление

- Проверка возвращает `ready`, `blocked`, `denied` или `error`, безопасную диагностику и, только для готового источника, отпечатки для последующего подтверждения регистрации.
- Неожиданная ошибка показывает «Не удалось проверить источник персонажа. Код обращения: …». Серверный лог содержит тот же ID, этап, класс исходного исключения, разрешённый машинный код, числовой код и имя файла с номером строки. Содержимое листа, SQL, произвольный текст исключения и права пользователя в лог не выводятся. Логирование проверки не создаёт запись операции или диагностики в базе ACS.
- В панели остаются текущий состав, выбранный лист и поля проверки. Неожиданная ошибка транспорта позволяет безопасно повторить проверку. Ключ операции и обработка неизвестного исхода сохраняются для регистрации.
- Для чужого листа сервер использует `AF_ACS_CharacterRegistrationGrant`. Актор берётся из MyBB, владелец и ID листа из источника, сессия из проверенного маршрута. Грант проверяет право GM, доступ к темам и привязку принятой анкеты. Тот же грант передаётся в CharacterSheets и чтение оборудования.

## Ручная приёмка

1. На вкладке «Состав» проверить собственный лист и лист другого игрока. Сверить имя, ID и выбранное столкновение.
2. Проверить лист с невалидной способностью KB и убедиться, что видна её диагностика. Исправить определение и повторить проверку.
3. Проверить источник без доступа и источник с некорректным HP. Сверить различие между отказом в доступе и исправимыми данными.
4. При неожиданной ошибке сверить код обращения с журналом `ACS entity_validate`. Убедиться, что панель позволяет повторить проверку.
5. Убедиться, что проверка не создала зарегистрированное существо. Для записи отдельно подтвердить регистрацию и проверить отказ при устаревшем отпечатке.

Проверены синтаксис изменённых PHP и JavaScript и `git diff --check`. Ручная приёмка на форуме остаётся за владельцем проекта.
