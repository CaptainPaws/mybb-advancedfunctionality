# ATF-ACS-03 — Боевой эпизод из формы создания темы

## Настройка и права

AdvancedThreadFields добавляет флаг `acs_enabled` в существующую таблицу `af_atf_groups` через штатное обеспечение колонок при установке и активации. По умолчанию флаг выключен. Форма **Groups → Edit group** сохраняет его и пересобирает кэш. Если несколько активных групп перекрываются, достаточно одной явной разрешающей группы. Пустая область (**All**) разрешения на ACS не выдаёт. Явный список использует обычное раскрытие дочерних форумов ATF.

В подходящем форуме выбор начинается с обычного эпизода. Боевой режим дополнительно требует доступного ACS, штатных прав MyBB на создание темы и `AF_ACS_SessionAccess::canCreate()`. Для модератора без ACP право ACS может приходить из существующего списка групп мастеров. Роль модератора сама его не выдаёт. Перед созданием сессии ACS повторно проверяет доступ к теме и правила текущего форума.

## Хуки и устойчивость повтора

1. `newthread_start` добавляет выбор режима и непрозрачный ключ формы к полям ATF. При предпросмотре и повторном показе формы сохраняются выбор и ключ из POST. Черновик сохраняется через MyBB без регистрации намерения и сессии. При публикации черновика выбор делается в новой форме.
2. `newthread_do_newthread_start` проверяет режим и допуск после штатной проверки CSRF. Если запрос уже связан с темой, сервер направляет инициатора к доступной теме. Если прежняя запись не содержит TID, повтор блокируется до выяснения результата.
3. `datahandler_post_insert_thread` получает проверенные MyBB данные непосредственно перед записью. На штатном writer уникальный ключ формы захватывается в InnoDB-таблице ATF `af_atf_acs_thread_intents`. Конкурирующий POST с тем же ключом не доходит до второй записи темы. Незаконченный захват после аварии сохраняется во избежание повторной вставки.
4. `datahandler_post_insert_thread_end` получает `tid` и `pid` из `return_values` MyBB. ATF сверяет автора, форум и первый пост на writer. Захват связывается с TID, уникальность которого защищает и повтор публикации того же черновика.
5. `newthread_do_newthread_end` с приоритетом 100 идёт после штатного сохранения полей ATF. Только при подтверждённой связи с опубликованной темой создаётся сессия через `SessionService::command('create', …)`. ACS назначает владельцем текущего автора команды через обычный контракт. Столкновение создаётся и запускается только через существующий мастер.

Ключ команды `atf-thread-create-<tid>` находится в штатном пространстве ключей ACS текущего инициатора. Повтор в мастере использует те же ключ, тему и причину. Сохранённый результат команды переиспользуется. Перед новой записью под блокировкой ACS проверяется отсутствие любой сессии темы. Независимый общий интерфейс ACS сохраняет свой прежний контракт.

При сбое ACS тема и поля сохраняются. Подтверждённый TID позволяет повторно открыть тему после потери ответа. В мастере можно повторить создание под прежним ключом. Если процесс оборвался до подтверждения TID, безопасный путь — найти тему в форуме и открыть настройку боя вручную. Для темы на модерации создание откладывается до публикации. При переносе настройки проверяются для нового форума, а удалённая тема недоступна через штатный контроль ACS. Существующие сессии и их история сохраняются.

## Интерфейс и ответственность

AdvancedThreadFields владеет настройкой группы и связыванием намерения с нативной темой. ACS владеет проверками прав, сессией, журналом команд, статусами и повтором. Adaptive Theme Framework выводит краткий статус через существующий `thread.meta`. Членство проверяется перед показом подтверждённого состояния сессии или столкновения. Инициатор видит своё ожидающее намерение, а действующий мастер получает ссылку «Настроить бой». Штатная панель остаётся единственной панелью механики. В старой теме из разрешённого форума ссылка ведёт к явному созданию через мастер. ACS runtime не добавляется через этот слот.

MyBB core, схемы ACS, Resolver и production publication не менялись.

## Проверки и ручная приёмка

- `git diff --check` прошёл. JS-файлы не менялись. PHP CLI недоступен. Автоматические тесты не создавались и не запускались.
- На установленном форуме проверить обычный и боевой режимы, мастера без ACP, модератора без права ACS, All, вложенные и перекрывающиеся группы.
- Проверить предпросмотр, публикацию черновика, тему на модерации, двойной POST, повтор после потери ответа и сбой ACS после создания темы. Сверить одну тему, один TID в намерении и отсутствие второй сессии.
- Проверить старую тему с уже существующей сессией и без неё, а также перенос и удаление. Сверить штатные редакторы, поля и доступ участников.
