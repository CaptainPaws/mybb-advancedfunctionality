# ACS-GM-06 — Исключение участника до начала боя

`encounter.participant_remove` принимает ID сессии, столкновения, участника и сущности, версии сессии, столкновения и участника, ключ операции, причину и подтверждение. Маршрут POST проверяет CSRF и действующие права GM. Команда выполняется только в активной сессии на этапе `preparation` при нулевом номере раунда. Запись запуска, любой сохранённый раунд, подтверждённый запуск в журнале и блокирующие обязательства запрещают исключение. Проверяются общий барьер незавершённых операций и публикации, активные подготовки и неприменённые предраундовые обязательства.

В действующей транзакции ACS проверяется принадлежность зарегистрированной сущности сессии и строки участия конкретному столкновению. Удаляется одна строка участия с CAS по её версии. Версии столкновения и сессии обновляются. Событие хранит ID сущности, ID исключённого участника, прежнюю сторону, версию и причину операции. Снимки, HP, AP, способности, экипировка, контроллеры, роли и регистрация сущности сохраняются. Повтор с тем же ключом и теми же параметрами возвращает прежний результат до повторного удаления. Позднее повторное добавление создаёт новую строку участия с прежним ID сущности.

Корзина открывает подтверждение внутри карточки состава через существующую навигацию ACS. После команды панель заново читает состав и полные счётчики столкновения и сторон. Предыдущая отметка готовности сбрасывается. Результат содержит прямую ссылку в «Недавние» на ту же сущность, включая сущности за пределами первой страницы списка.
