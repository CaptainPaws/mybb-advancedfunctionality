# ACS-11-HOTFIX — Открытие списка сессий ACP

`AcpReadModel::sessions()` передавал в `AF_ACS_Repository::json()` данные привязки курсора без обязательного поля `schema_version`. Сериализатор выбрасывал `ACS_INVALID_INTEGER` до запроса списка, в том числе на пустой базе. В отчёте с установленного форума указан `error_id=ba3e42cf03aaac1101146d0c8692fbac`.

В привязку добавлено `schema_version=1`. Это единственный вызов `self::json()` в `AcpReadModel.php`. Создание и чтение курсора используют один вычисленный хеш для области ACP, текущего UID и фильтров. Формат курсора `bind/after` и шифрование в `AF_ACS_Archive` сохраняются. При смене пользователя или фильтров нужно открыть первую страницу. Каждая страница повторно проверяет native-доступ к темам. При отсутствии доступных записей отображается штатное сообщение о пустом списке. Ссылка на следующую страницу сохраняется, если выборка ещё не исчерпана.

Ожидаемый отказ в доступе к теме по-прежнему скрывает её запись. Неожиданные ошибки передаются в существующий обработчик. ACP показывает безопасный код и идентификатор. Диагностика списка записывается с операцией `acp_sessions`. Код причины в поле `phase` приводится к нижнему регистру, который требует Repository. Если запись в БД не удалась, безопасный код и тот же идентификатор пишутся в журнал PHP.

`git diff --check` прошёл. PHP CLI отсутствует. Автоматические тесты не создавались и не запускались. Ручная приёмка включает пустой список, существующую сессию с доступом к теме, фильтры и переход между страницами.
