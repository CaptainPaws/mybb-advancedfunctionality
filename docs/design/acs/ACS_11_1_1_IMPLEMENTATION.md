| `assets/thread-panel.js` | Единое DOM-состояние, открытие/сворачивание, фильтры, mobile-панель, компактная строка, локальный countdown |

| `manifest.php` | Контекстный `thread_panel`, факт `has_acs_panel` для CSS/JS; cache version 1111 |

Показываются название, подготовка/активно/пауза/ожидание результата (`pending_resolution`)/завершено, номер раунда, собственная группа, общий остаток AP с учётом pre-round commitment и состояние хода. Движок использует свободный порядок ходов: панель сообщает об этом и показывает доступные групповые ходы, не выдумывает единственного активного исполнителя.

Питомцы и source-group summons следуют владельцу **группы**, не создают отдельного AP. Самостоятельные NPC остаются отдельными группами. HP, ресурсы, активные статусы и барьеры читаются пакетно из материализованного состояния; подробные характеристики не загружаются. Время показывается только при существующем дедлайне, на паузе не уменьшается. Countdown не исполняет дедлайн и не подтверждает актуальность сервера; состояние обновляется обычным запросом страницы, polling отсутствует.

Ссылки ведут в существующие конструктор, архив, добычу и GM-панель. Конструктор предлагается ролям регистрации, GM-инструменты — `can_manage`; конечные контроллеры повторно проверяют права и доступность действий. Журнал и добыча доступны участникам сессии через существующие серверные gates. Тяжёлые формы открываются только по явному URL.

## Видимость и ограничения текущих контрактов

- SessionService проверяет native topic access, роль и соответствие TID. Скрытые строки отбрасываются на сервере до создания HTML, фильтров и групп. Общие количества участников не выводятся.
- Точные данные доступны владельцу player control group и GM/audit audience. Observer не получает права управления.
- Для остальных участников текущая awareness должна разрешать `identified` и `canTarget`. В HTML используется только разрешённое имя. Реальные side/group IDs, тип, HP, ресурсы, статусы, барьеры, AP и дедлайны таких участников не передаются. Чужие видимые участники имеют отдельные безопасные UI-группы без раскрытия механических связей.
- В checkout нет утверждённой full/approximate/hidden проекции числового состояния. Приблизительные HP и чужие групповые сведения не изобретены. Фильтры сторон работают для разрешённых точных групп. Это ограничение покрытия A1.53 требует сверки с ACS-10.4.3.
- Существующий AudienceService имеет bounded participant scope (201 строк) и дополнительные controller/state queries на участника. Панель не использует этот предел как total, не рисует заглушки и не сообщает о скрытом остатке; неопределённое знание закрывается. Новые запросы HP/ресурсов/статусов/барьеров пакетные, однако полное отсутствие N+1 и количественные performance thresholds не заявляются. AudienceService также может косвенно загрузить QueryService при проверке некоторых copy-ability статусов; полный lightweight view contract требует отдельной сверки зависимости.
- Выбирается одно текущее столкновение выбранной сессии: active/paused/pending_resolution, затем preparation/ambush_ready, затем последнее терминальное. При нескольких сессиях без explicit selection — первая разрешённая с существующим столкновением; ссылки сессий сохранены. Независимые панели не размножаются.

## Desktop / mobile / ATF

Desktop использует полную панель над постами. После прокрутки её начала появляется компактная кнопка с названием, состоянием, раундом и собственным AP. Нажатие возвращает к той же панели. Mobile сначала показывает компактную кнопку; полные сведения открываются адаптивной панелью с вертикальной прокруткой.

Один details/body используется в обоих режимах; resize и сворачивание не пересоздают карточки или фильтры. Без JS доступны native details и разрешённые ссылки. Доступны клавиатурные кнопки, focus outline, aria-controls/expanded и Escape с возвратом фокуса.

Положение compact/mobile рассчитывается по текущим bounding rectangles `.af-am-navigation`, `.atf-post__topbar`, `.atf-post__meta-line`. Нет фиксированного произвольного top-offset, записи в стили ATF или изменений postbit. Scroll handler объединяется через requestAnimationFrame; ResizeObserver следит за размерами панели/навигации. Реальная совместимость слоёв и геометрии требует ручной проверки на установленной теме.

## Ручная приёмка владельцем

1. Обычный showthread без ACS: нет панели/её JS и загрузки нового query stack.
2. Игрок: правильный round, AP с pre-round расходом, HP/ресурсы; питомец и summon в своей группе без нового бюджета.
3. GM и observer: сравнить HTML и фильтры, проверить скрытых участников и отсутствие утечек через агрегаты, видимые чужие имена и недоступные числа.
4. Все пять состояний, отсутствие дедлайна, countdown, пауза и возобновление после обновления страницы.
5. Длинные имена, несколько сторон, side/group filters, пустая выборка без сообщения о скрытых существах.
6. Desktop scroll/zoom, navigation resize, sticky postbit/meta-line, mobile portrait/landscape и клавиатурная навигация. Панель не должна перекрывать защищённые ATF поверхности.
7. Фильтры сохраняются после close/open и resize; mobile открывает тот же body. Проверить работу без JS.
8. Выполнить PHP syntax checks и сверить full/approximate/hidden и performance contracts с отсутствующим ACS-10.4.3 до merge.
