# ACS-TESTPACK-01A — Восстановление страницы ACP

## Причина

В `main` после PR #1109 `Testpack::render()` вызывал `AF_ACS_TestpackDefinitions::entries()` до `prerequisites()` и вне блока `try`. Генератор сначала обращался к `af_kb_arpg_primary_elements()`, затем к `af_kb_arpg_character_stat_keys()`. При незагруженном KB первая из них приводит к PHP `Error: Call to undefined function af_kb_arpg_primary_elements()` до вывода заголовка. Если отдельно загружен модуль стихий, аналогично может завершиться следующий вызов.

Обе функции присутствуют в исходниках. Реестр стихий объявлен в `knowledgebase/modules/arpg_elements.php` и загружается bootstrap KB. `af_kb_arpg_character_stat_keys()` объявлена в `knowledgebase.php` и возвращает ключи основного реестра. Точный текст ошибки на рабочем форуме по журналу остаётся `NOT_VERIFIED`. Проверка `php -l` в #1109 проверяла синтаксис и не исполняла путь ACP.

## Исправление и проверка маршрута

- После проверки прав ACP выводит заголовок, затем подготавливает зависимости внутри `try`. Генератор получает `af_kb_arpg_character_stat_registry()` и реестр 17 основных стихий через аргументы. Два существа используют штатные ключи `combat_stats` и по 17 явных записей RES. Ключ `status_resist` остаётся в формате KB, а отображение в `status_resistance` выполняет существующий адаптер ACS.
- Страница показывает статус, причины блокировки для каждого компонента и список определений при доступном контракте KB. При ошибке загрузки или генерации ACP показывает безопасный код. SQL, пути и трассировка в сообщении отсутствуют.
- Перед POST проверяются доступность аддонов, настройки KB/Shop, функции владельцев, схема ACS, таблицы Inventory, CharacterSheets и Balance, столбцы таблиц записи, InnoDB, уникальные ключи KB/Shop и активные типы KB со стихией огня.
- Статически сверены обязательные колонки создания KB, блока данных и журнала, а также поля магазина, категории и позиции. Валидация KB, закрепление ссылок существ и проверка источника Shop по-прежнему проходят через действующие функции владельцев. Цены по-прежнему конвертируются в minor units. При INSERT ID читается сразу из MyBB writer.
- MyBB 1.8.40 может завершить запрос при ошибке стандартного `insert_query()`. Записи установщика используют тихий режим `write_query(..., 1)` и явную обработку отказа, чтобы пройти через rollback и показать диагностический код. Транзакция, блокировка, реестр и условия однократной установки остаются прежними. Реестр читается с writer, включая чтение после commit. Чужие ключи останавливают установку до записи.
- Повторный POST требует действительного CSRF и подтверждения. GET только отображает данные. После установки сохраняются ссылки на публичные определения KB и арсенал, а связи девяти товаров сверяются по данным реестра.

## Проверки

`git diff --check` и `php -l` изменённых PHP-файлов. Все девять шагов ручной приёмки остаются `NOT_VERIFIED`, включая открытие ACP при отключённой зависимости, реальную запись и rollback, проверку ссылок и девяти товаров, повторный POST и сохранение ручных правок после реактивации.
