# INV-LIFECYCLE-01 — Активация AdvancedInventory с готовой Owner Schema

## Причина

Общий контроллер AdvancedFunctionality при «Включить» повторно вызывал `af_advancedinventory_install()`, даже если Inventory уже установлен. В `install()` и в прежнем `activate()` первым выполнялся `af_advinv_maintenance_gate()`. После создания Owner Schema защитная проверка запрещала старую процедуру обслуживания с кодом `INV_MAINTENANCE_REQUIRES_OFFLINE_PROTOCOL`. Контроллер перехватывал исключение, а диагностическая запись Inventory отсутствовала, поэтому ACP показывал общий текст.

## Разделение операций

- Для установленного Inventory контроллер вызывает `activate()`. Первичная установка использует прежний защищённый `install()`; флаг включения выставляется штатным контроллером после активации. Bootstrap в ACP не запускает старую нормализацию.
- Активация сначала читает контракт Owner Schema и обязательные таблицы и поля Inventory. Она также проверяет наличие данных, требующих старой нормализации или отдельного разбора импорта. Заказы с ключом современного checkout уже выдают предметы в своей транзакции и не считаются очередью старого импорта.
- После проверки активация добавляет отсутствующие настройки, синхронизирует поставляемые мастер-шаблоны и управляемые маршруты. Значения существующих настроек и шаблоны темы сохраняются.
- Обновление таблиц, переименование старого хранилища, нормализация предметов и импорт из Shop остаются в процедурах установки и обслуживания. Их прежняя защита `af_advinv_maintenance_gate()` сохранена. Активация не изменяет Owner Schema, предметы, версии владельцев, экипировку и резервы. Защита Inventory writers остаётся действующей.

## Диагностика и действия в ACP

Штатная lifecycle-диагностика записывает этап и машинный код. При неизвестной ошибке отображается `INV_LIFECYCLE_FAILED`. SQL, stack trace и пользовательские данные в диагностике отсутствуют.

| Код | Действие |
| --- | --- |
| `INV_SCHEMA_NOT_READY` | Открыть **ACP → AdvancedInventory → Подготовка схемы для ACS**, сверить таблицы и использовать отдельное подтверждение для создания недостающих. |
| `INV_STORAGE_UPGRADE_REQUIRED` | Сверить обязательные таблицы и поля Inventory и согласовать отдельное обновление в обслуживании. |
| `INV_MAINTENANCE_REQUIRES_OFFLINE_PROTOCOL` | Запланировать отдельную операцию нормализации в обслуживании. Старые процедуры сохраняют блокировку при активном Owner Protocol. |
| `INV_LEGACY_IMPORT_REVIEW_REQUIRED` | Сверить старые записи Shop с уже выданными предметами до отдельного импорта. Отсутствие отметки о миграции само по себе не разрешает повторную выдачу. |

## Проверки и NOT_VERIFIED

Точечные `php -l` и `git diff --check` прошли. Автоматические тесты не создавались и не запускались.

На warprift.ru остаются **NOT_VERIFIED** включение аддона, доступность страницы Inventory, сохранность предметов и экипировки, статус Owner Schema и повторная проверка источника. Фактическая регистрация персонажа проверяется отдельно через ACS.
