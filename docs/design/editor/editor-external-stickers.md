# AdvancedEditor 1.1.5: внешние пользовательские стикеры

## Что было до задачи 7

В `2a07950e` уже присутствовали два режима в «Своих стикерах», сохранение URL
за текущим UID без локального файла, выбор стикера и вставка `[img]URL[/img]`,
исключение ссылок из квоты и удаление записи. Повторная реализация этих механизмов
не потребовалась. Проверка URL допускала HTTP и не проверяла изображение; название
было фиксированным. Метки источника и заглушки отсутствовали. Полный uninstall
удалял таблицы стикеров, хотя обычная активация данные сохраняла.

## Дополнения

- Новые ссылки принимаются только по HTTPS на стандартном порту 443, без логина,
  пароля, фрагмента и управляющих символов. Скобки в пути/параметрах нужно кодировать,
  чтобы ссылка сохраняла совместимость с форматом BBCode.
- При добавлении сервер проверяет HTTP-статус, Content-Type и сигнатуру изображения
  через Fileinfo и `getimagesizefromstring()`. Поддерживаются PNG, JPEG, GIF и WebP,
  включая прямые ссылки без расширения, если проверка подтверждает изображение.
- Для проверки читается только начальный фрагмент до 256 КиБ в оперативную память.
  Общий HTTP timeout — 8 секунд, connect timeout — 3 секунды, заголовки ограничены
  64 КиБ. Запрашивается Range; если источник игнорирует Range, чтение прерывается
  на пределе. Этот предел относится к проверяемому фрагменту, а не к размеру
  внешнего файла. Изображения, формат которых не удаётся подтвердить по фрагменту,
  отклоняются. Полная декодируемость и неизменность будущего ответа не гарантируются.
- Перенаправления не выполняются. Все найденные A/AAAA адреса должны быть публичными;
  внутренние, loopback, link-local, multicast и специальные диапазоны запрещены.
  cURL соединяется с проверенным IP через DNS pinning, TLS-проверка включена,
  фактический IP сверяется после запроса. При наличии forward proxy операция
  запрещается, поскольку прокси может обойти DNS pinning. Прокси окружения не
  отключается. Требуются PHP cURL и Fileinfo.
- Название вводится пользователем; пустое заменяется на «Внешний стикер».
  URL и название экранируются при отображении, UID берётся из сессии MyBB.
- В БД добавлен столбец `source` со значениями `local` / `url`. Для существующих
  ссылок тип определяется по уже сохранённым `is_user_sticker=1`, пустому `path`
  и HTTP(S) URL. Владельцы, URL и файлы не меняются. Старые HTTP-ссылки сохраняются;
  HTTPS-проверка применяется к новому добавлению. `ext` новой записи соответствует
  распознанному формату.
- В пользовательском каталоге и серверном списке недавних стикеров показывается
  метка URL. При ошибке загрузки внешнего превью появляется доступная заглушка
  «Недоступен», а возможность удалить запись сохраняется. Нет синхронной серверной
  перепроверки всех изображений при открытии меню.
- Формат вставки остаётся `[img]URL[/img]`. Внешние записи имеют пустой `path`,
  не создают постоянной копии и не расходуют локальную квоту. Удаление не отправляет
  запрос на внешний хостинг и не пытается удалить чужой файл.
- Каталог стикеров, категории и недавние записи сохраняются также при полном
  uninstall AdvancedEditor, затем используются повторной установкой. Остальная
  процедура uninstall не менялась. Локальные и системные стикеры сохраняют прежние
  пути, загрузку, квоты и формат вставки.

## Проверки

Изолированная MariaDB, PHP 8.2 и Chromium:

- `editor_sticker_external_security.php`: HTTPS, протоколы, авторизация, порт,
  внутренние/специальные IPv4/IPv6, смешанный DNS, перенаправления, MIME и сигнатуры,
  HTML/SVG, отказ при forward proxy. Транспортные ответы подставлены; в реальный
  сторонний аккаунт или хостинг тестовые изображения не отправлялись.
- `editor_sticker_http_regression.py`: реальная БД и multipart; сохранение названия,
  источника и GIF, изоляция UID, метаданные вместо локального файла, неизменная квота,
  удаление и регрессия локальной загрузки. DNS/ответ внешнего источника заменяет
  тестовый инспектор; бизнес-обработчик и сохранение используются настоящие.
- `editor_sticker_browser.cjs`: реальные модалка и backend; добавление именованного
  внешнего GIF, метка, заглушка при ошибке превью, прежний BBCode в редакторе,
  локальные загрузка/удаление, индикатор квоты и мобильная ширина.
- `editor_sticker_fixture.php --init`: повторная миграция и сохранность прежнего HTTP
  URL и UID. `--lifecycle`: реальный uninstall и два activate; URL-записи сохраняются.
- Пройдены `advancededitor_installed_asset_paths_regression.php` и
  `signature_editor_regression.php`.

JavaScript и CSS стикеров версионируются по хешу содержимого. После установки
обновлённых файлов нужно обновить страницу с редактором. Системные альбомы Gallery
и её провайдеры не участвуют в загрузке или проверке стикеров.
