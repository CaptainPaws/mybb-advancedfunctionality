# KB-ABILITIES-01 — Каталог готовых способностей

## Публичная страница и источник данных

`/kb.php?type=arpg_ability` выводит карточки активных записей из `af_kb_entries`. Поиск проверяет вхождение строки в русское и английское названия. Фильтры комбинируются, а ссылки пагинации сохраняют их значения и сортировку. Карточка открывает действующую страницу механики в KB. Редакторы могут открыть прежний список управления со скрытыми и неактивными записями по ссылке «Управление записями».

Типы способностей и категории урона берутся из реестров KB. Фильтр «Без урона / поддержка» использует существующий ключ `healing`. Каталог включает в него способности с однозначно определёнными эффектами без урона, сохраняя исходный `damage_type` в определении. Устаревшие значения урона остаются отдельными значениями фильтра. Каталог показывает 17 основных стихий и действующие публичные дочерние направления. Фильтр основной стихии включает карточки её направлений. Фильтр направления выбирает точный ключ.

Фильтр оружия использует активные ключи KB `weapon_type` и группирует штатные ключи в существующие слоты ARPG Items.

| Слот | Ключи KB |
| --- | --- |
| `weapon_one_hand` | `sword` |
| `weapon_two_hand` | `greatsword` |
| `weapon_polearm` | `spear` |
| `weapon_ranged` | `bow`, `firearm` |
| `weapon_catalyst` | `catalyst` |

Новые активные ключи KB доступны как точные значения. Для включения нового типа в фильтр слота потребуется сопоставление с его группой.

## Метаданные применимости

В существующем редакторе JSON определения KB можно добавить необязательный объект `rules.ability_catalog`. Пример для огненной способности ближнего боя с двуручным оружием:

```json
{
  "ability_catalog": {
    "version": 1,
    "weapons": ["weapon_two_hand"],
    "distance": "melee",
    "required_element": "fire"
  }
}
```

- `weapons` принимает список точных ключей KB или существующих слотов. `["none"]` означает, что оружие не требуется. `["any"]` объявляет универсальную применимость к оружию. Оба значения проходят проверку независимо от экипировки. Фильтр конкретного оружия включает такие записи. Выбор «Без требования к оружию» или «Универсальное» показывает соответствующее явное значение.
- `distance` принимает `melee`, `ranged` или `any`. Каталог сохраняет исходную числовую дальность механики отдельно от этой классификации.
- `required_element` принимает канонический ключ основной стихии, точный ключ публичного направления, `none` для персонажа без стихии или `any` для отсутствия требования. Корень подходит требованию основной стихии. Для требования дочернего направления совпадение одного корня даёт статус «требует уточнения», соседнее направление даёт «не подходит».
- `purpose` задаёт `attack`, `heal`, `defense`, `buff`, `debuff`, `control` или `mixed`, если набор эффектов неоднозначен. Для известных типов эффектов каталог использует хранимые `effect_type` и `kind`.

Схема расширяется только необязательным объектом в JSON. Старые записи остаются в каталоге без подтверждения отсутствующих требований. Неизвестные значения фактического реестра сводятся к неизвестной применимости при чтении. Условия механики в `conditions`, `application_conditions`, `upgrade_requirements` и ссылки определений сохраняют действующую семантику ACS. Каталожные метаданные используются для отбора и подсказок при выборе.

## Read-only API для ATF

`GET /kb.php?action=kb_ability_catalog`. При отключённом псевдониме страницы доступен `/misc.php?action=kb_ability_catalog`. Доступ определяется политикой просмотра KB. Элементы ответа проходят проверку активности и флагов видимости `catalog`, `search`, `internal`, в том числе при запросе от редактора.

| Параметр | Значение |
| --- | --- |
| `q` | Фрагмент названия, до 100 символов |
| `ability_type`, `damage_type` | Ключи соответствующих реестров KB |
| `element`, `direction` | Основная стихия или `none`, точный ключ направления |
| `weapon` | Точный ключ оружия, слот, `none` или `any` |
| `distance`, `purpose` | Значения каталожных метаданных |
| `sort` | `title` (по умолчанию), `type`, `element` |
| `page`, `per_page` | Номер страницы с единицы и до 50 записей на страницу |
| `context_element`, `context_direction`, `context_weapon`, `context_distance` | Контекст персонажа для оценки применимости. При отсутствии используются соответствующие фильтры, если они заданы |

Пример оценки относительно двуручного меча для огненного персонажа на ближней дистанции, с сохранением всех статусов среди найденных карточек:

```text
/kb.php?action=kb_ability_catalog&context_weapon=greatsword&context_element=fire&context_distance=melee&per_page=12
```

Ответ содержит `success`, `items`, `total`, `page`, `per_page`, `pages`. Карточка содержит `kb_key`, локализованные `title` и `description`, `type`, массивы `element`, `direction` и `damage_type`, `purpose`, объект `applicability`, `icon`, `definition_id`, `url` и `compatibility`. `description` передаётся как сохранённый текст для безопасного отображения текстовым узлом. Идентификатор определения представляет собой непрозрачный SHA-256 от сохранённых полей правил и метаданных. Для ссылки между аддонами используется `kb_key`.

`compatible` означает, что все три оси подтверждены. `incompatible` означает явное несовпадение хотя бы по одной оси. `needs_review` означает, что часть требований или контекста отсутствует, неизвестна либо задана слишком широко. Клиент может передать только `context_*` вместе с желаемыми фасетами, чтобы получить все три статуса без ограничения выборки контекстом персонажа.

API готов для отдельного подключения к выбору готовых способностей в ATF. Текущая анкета и её редактор пользовательских способностей не менялись. Отдельная таблица, клиентская загрузка всего каталога и механические вычисления для поиска не требуются.

## Производительность и приёмка

Сервер читает активное подмножество по префиксу индекса `type_active_sort` пакетами по 200 строк, проецирует поля фильтров из существующих JSON и хранит ключи сортировки для совпадений. Описания и иконки загружаются только для выбранной страницы. Стоимость фильтрации остаётся линейной по числу активных способностей после SQL-поиска по названию. Общего кэша и миграции БД нет. Стили фильтров выводятся на странице каталога, JavaScript для каталога не добавлен.

`git diff --check` и `php -l` для изменённых PHP-файлов выполнены. JavaScript-файлы не изменены. Ручная приёмка ниже требует стенда MyBB с опубликованными и закрытыми записями.

1. Найти способность по фрагменту русского названия и по фрагменту перевода. Проверить, что `%` и `_` ищутся буквально.
2. Выбрать основную стихию с дочерними направлениями. Убедиться, что основная стихия включает её направления, а точный фильтр исключает соседние.
3. Применить фильтры `physical`, `elemental`, `true` и `healing` к способностям с соответствующими эффектами.
4. Проверить фильтры двуручного оружия и конкретного лука. Сравнить статусы огненной способности из примера выше в контексте `greatsword` и `bow`.
5. Совместить поиск, тип способности, стихию, урон, дистанцию, назначение и оружие. Проверить сортировку по названию, типу и стихии.
6. Проверить лечение с `["none"]`, дистанцией `any` и стихией `any`. Оно предлагается и с мечом, и без оружия. Старая запись без метаданных даёт `needs_review`.
7. Передать точное требуемое направление, соседнее направление и только общую основную стихию. Ожидаются соответственно `compatible`, `incompatible`, `needs_review`, если остальные оси подтверждены.
8. Сравнить HTML и JSON при запросе от гостя и редактора. Неактивные и скрытые записи должны отсутствовать в обоих результатах и счётчиках. При закрытом KB пользователь без прав получает отказ. POST к API возвращает 405.
9. На выборке больше одной страницы перейти на следующую страницу, сохранив параметры. Проверить, что HTML и JSON содержат только карточки текущей страницы и что JSON ограничивает `per_page` значением 50.
