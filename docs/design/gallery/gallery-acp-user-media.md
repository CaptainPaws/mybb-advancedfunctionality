# AdvancedGallery: медиа пользователей в ACP

`admin/index.php?module=advancedfunctionality&af_view=advancedgallery&ag_tab=users`

Вкладка «Медиа пользователей» показывает только владельцев зарегистрированных медиа: поиск имени/UID, произвольную неактивность (в том числе 30/90/180/365 дней), сортировку и серверную пагинацию. Карточка медиатеки включает все альбомы владельца, независимо от системного назначения, видимости и модерации. Изображения выводятся по 24; пользователи — по 30. При отсутствии отдельной миниатюры выводится заглушка, оригинал автоматически не загружается.

## Проверка связей

Проверка запускается администратором, обрабатывает до 100 записей одного источника за запрос и сохраняет курсор. Её можно приостановить и продолжить, в том числе после возвращения на страницу. Для простых и составных первичных ключей используется курсор по ключу. Открытие ACP само по себе не сканирует посты и не проверяет доступность внешних сайтов.

Проверяемые источники:

- `users.avatar`, `users.signature`, `userfields`, в том числе ссылки других пользователей;
- посты всех пользователей; темы из `af_character_workflow` отмечаются как анкеты;
- текстовые/JSON-поля таблиц AF с первичным ключом: APF/APUI, маски и пресеты AdvancedAppearance, CharacterSheets, конструктор подписей и остальные данные аддонов;
- явные Gallery ID в JSON/колонках известных потребителей: `af_aa_presets`, `af_aa_assignments`, `af_asb_signatures`, прежняя `af_apui_signature_builder`.

Числовой `media_id` неизвестного каталога не считается доказанной связью с Gallery. Таблицы Gallery, служебные журналы, кэш и ledger не принимаются за публикацию изображения. Если текстовый источник не имеет первичного ключа или исчез во время проверки, аудит считается частичным, а изображения без подтверждённых связей остаются непроверенными.

«Используется» означает найденный явный Gallery ID или совпавший прямой URL/локальный путь. «Не найдено использование» означает отсутствие связей в проверенных источниках на момент проверки. «Не проверено» используется до завершения полного аудита и для новых записей после его старта. Произвольные CSS, сторонние плагины вне AF, изменённые URL, внешние документы и другие сайты не могут быть полностью проверены. Аудит не является транзакционным снимком всего форума; при активном редактировании его следует повторить. Перед подготовкой и каждым пакетом удаления повторно проверяются актуальные известные источники. Если запрос даёт более 100 совпавших записей, результат считается непроверенным.

`appearance_retained` сохраняется как отдельное консервативное закрепление оформления: оно само по себе не выдаётся за доказанную текущую публикацию. Такие записи защищены от очистки по умолчанию.

## Удаление и защита

Обычный массовый выбор исключает подтверждённо используемые, вручную защищённые и ранее закреплённые записи. Их можно выбрать вручную, но для удаления в диалоге требуется отдельное разрешение; для непроверенных записей предусмотрено ещё одно разрешение. Нет автоматического удаления по результатам аудита и нет кнопки «Удалить всё».

Сервер создаёт случайное задание на 15 минут, привязанное к администратору и владельцу. Клиент не передаёт разрешённый список UID. Каждый ID проверяется по БД; каждый пакет обрабатывает до пяти выбранных записей. Все операции требуют POST, MyBB CSRF и ACP-прав; состояние задания сериализуется через `GET_LOCK`. В транзакции удаления повторно проверяются владелец, закрепление, ручная защита и метаданные использования.

Локальные файлы удаляются общим механизмом Gallery. Допускаются только пути внутри `uploadspath/af_gallery/UID/`, без обхода каталога и символических ссылок ниже корня Gallery. Файлы сначала переименовываются в том же каталоге; при ошибке SQL/файловой операции восстанавливаются. Совместно зарегистрированные пути не удаляются физически. Число освобождённых байт отражает фактически удалённые оригиналы; миниатюры и внешние записи в него не входят. Редкие ошибки завершения файловой очистки сохраняются в журнале. Внешние операции не отправляют запросов удаления провайдерам.

`af_gallery_logs` хранит администратора, время, UID, ID медиа и параметры разрешений. В медиатеке показаны последние 20 административных действий. Суммы Gallery и квоты продолжают вычисляться из зарегистрированных локальных оригиналов, поэтому после удаления обновляются вместе со страницей ACP.

Схема дополняется `cleanup_protected`, `usage_flags`, `usage_checked_at` и двумя служебными таблицами аудитов/заданий. Повторная активация сохраняет значения и файлы. Ручная защита касается административной очистки и не меняет использование изображения владельцем. Перемещение допускает только альбомы того же владельца и сохраняет ограничения системных альбомов провайдеров.

## Проверка

Выполнены PHP lint, `node --check` и точечная временная проверка на изолированной MariaDB: строгие GROUP BY, составные курсоры, фильтры, принадлежность UID, CSRF, защита/подтверждения, перенос, модерация, локальные оригиналы/миниатюры, внешние записи, запрещённые пути/символические ссылки и журнал. Полные браузерные E2E не запускались; визуальную проверку выполняет заказчик.
