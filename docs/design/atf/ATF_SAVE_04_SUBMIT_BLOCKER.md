# ATF-SAVE-04 — Блокировка отправки editpost

## Что установлено

В шаблоне Adaptive Theme Framework `#editpost` содержит штатную кнопку `submitbutton`, `action=do_editpost`, нативное сообщение и маркер вставки ATF. `af_tf[fieldid]` и `af_atf_form_present` вставляются в этот маркер. Шаблон редактора полей не открывает дополнительную форму. Каталог способностей создаёт отдельную форму фильтров в диалоге вне формы анкеты. Для пользовательской темы возможны расхождения с репозиторным HTML. Анонимный запрос к editpost на warprift.ru показал форму входа и не дал разметку анкеты.

Установлены два независимых пути, способных остановить запрос до PHP.

1. **До события submit.** Сохранённые характеристики принимают числа произвольной точности, а браузерное поле требовало `step=0.01`. Кулдаун и длительность эффекта требовали `step=1`, отдельные контролы ограничивали диапазон. Сохранённое значение вне шага или диапазона блокирует отправку даже при редактировании одного имени. Скрытый CSS нативный textarea также может участвовать в constraint validation, если шаблон добавляет ему `required`.
2. **После события submit, до POST.** `bindEditpostFormGuards()` находит `textarea[name=message]` отдельно от проверки запуска редактора. `bindSubmitSync()` мог привязать обработчики к структурированной форме несмотря на `data-af-ae-skip`. При рассинхронизации исходного и отображаемого текста его submit-guard вызывает `preventDefault()`. В штатной структурированной форме нативный текст подготавливается существующим серверным контрактом.

Срабатывание конкретного пути на warprift.ru и наличие события submit или POST в исходном инциденте остаются `NOT_VERIFIED`. #1112 устранил часть скрытых контролов эффектов и исправил запись и диалог. Проверка шага сохранённых значений и отдельная привязка AdvancedEditor оставались. #1113 работает после POST и не может устранить отмену в браузере.

## Исправление и наблюдаемость

- Точность характеристик соответствует серверному числовому формату. Для ранее сохранённых чисел способностей ограничения, которым не соответствует исходное значение, откладываются до изменения конкретного контрола. Скрытые и неактивные контролы эффектов по-прежнему исключаются из браузерной проверки.
- Структурированный `message` сохраняет имя и отправляется в составе формы. У него убирается только `required`; AdvancedEditor не подключает submit-guard к этому полю и повторно проверяет владельца перед обработкой. Остальные формы и проверка MyBB сохраняют прежнее поведение.
- Для editpost проверяется принадлежность кнопки, маркера и полей форме. При `invalid` выводится причина, видимый контрол выделяется и получает фокус. Отмена click или submit JavaScript отображается отдельно. Состояния клиента видны по `data-af-atf-submit-state`, включая `html-validation-blocked`, `js-submit-blocked` и `submit-accepted`. Последнее означает разрешённое событие, подтверждение доставки находится в Network.
- Ответ сервера показывает `X-AF-ATF-Edit` со стадией `post-received`, `validation-failed`, `persistence-failed` или `persistence-confirmed`. Пользовательские ошибки валидации и сообщение с диагностическим ID при отказе записи остаются штатными. Обработчики записи, PID/TID/FID и схема не менялись. Текст полей в диагностике отсутствует.

## Проверки

Выполнены `git diff --check`, `node --check` изменённых JS и `php -l`. Ручная проверка с правом редактирования на warprift.ru остаётся `NOT_VERIFIED`.

Для приёмки открыть Network с сохранением журнала и отправить изменение только имени. Проверить POST editpost с полями ATF, по ответу сверить стадию, затем открыть тему и редактор. Повторить для описания, характеристики, собственной, готовой и смешанной способности. Проверить отправку без изменений способностей, а также видимый обязательный элементальный эффект без стихии и сохранённые дробные значения. При отказе различать состояние формы и заголовок ответа; публиковать только состояние и диагностический ID.
