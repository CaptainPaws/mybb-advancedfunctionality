# ATF-KB-ABILITIES-02 — Готовые способности в анкете

В поле типа `character_abilities` (в штатной конфигурации имя поля `character_abil`) доступны «Создать свою» и «Выбрать из KB». Обе формы добавляют строку в один список с пределом восемь записей. Порядок списка задаёт порядок слотов. Готовая запись отображается отдельной карточкой с кратким описанием и ссылкой на механику. Из любой карточки каталога можно начать собственную способность с тем же названием и описанием.

## Каталог и контекст

Модальное окно монтируется в существующий ATF Modal Host. Первый запрос выполняется при открытии. API KB-ABILITIES-01 выдаёт значения фильтров при `options=1`, ограничивает выборку статусом `compatibility` до пагинации и принимает `independent_context=1`, чтобы фильтры просмотра не заменяли контекст анкеты. В исходном режиме показываются совместимые карточки, с приоритетом совпадающей стихии и точного направления. Доступны вкладки через фильтр применимости и серверный переход между страницами.

| Вход | Источник |
| --- | --- |
| Стихия и направление | `character_element`. Если значение соответствует публичному направлению KB, передаются его корень и точный ключ |
| Оружие анкеты | `character_weapon`, затем `character_weapon_type`, затем `weapon_type`. Те же имена читает мост CharacterSheets |
| Дистанция | Дистанция остаётся поисковым фильтром. Подтверждённого поля дистанции в анкете нет |
| Происхождение и архетип | Поля существуют, но контракт применимости способностей KB не определяет ограничений по ним |
| Фактическая экипировка | Учитывается при боевой подготовке по существующим путям Inventory и ACS. На новой анкете используется выбранное оружие |

При изменении стихии или оружия следующий запрос использует актуальные значения формы. Явно несовместимые способности доступны для просмотра и создания собственной версии. Строку со статусом «требует уточнения» можно добавить для проверки. Выбор в анкете сам по себе не предоставляет права использования в ACS.

## Сохранение и синхронизация

DataHandler повторно проверяет источник `arpg_ability`, ключ и доступность записи, сверяет выбранную версию и отбрасывает явно несовместимые новые ссылки. Он записывает только `ability_kb_key`, тип источника, порядок, данные представления из KB и боевой pin `ability_definition_version` / `ability_fingerprint`. Поля механики, переданные клиентом, не попадают в готовую строку. Резервные хуки сохранения не перезаписывают проверенный список сырым POST. Ошибки доступны через стандартный вывод ошибок MyBB.

Существующая ссылка сохраняется из прежней серверной записи при повторной отправке того же ключа и версии. Для скрытой, удалённой или изменённой записи при открытии анкеты показывается сообщение. Чтобы принять новую версию, игрок удаляет строку и выбирает актуальную карточку. Идентификатор каталога учитывает текстовые изменения и правила. Боевой pin использует действующий отпечаток механических правил, поэтому редакционная правка описания сама по себе не ломает боевой pin.

Мост анкеты передаёт смешанный список CharacterSheets через существующий `character_abilities`. Разрешение закреплённой ссылки выполняется только для явно помеченной строки в нормализации KB. ACS и CharacterSheets используют авторитетное определение с совпадающим pin. При исчезновении определения или смене механического отпечатка новый расчёт сообщает об ошибке. Формат и жизненный цикл уже созданного боевого снимка остаются прежними. Проверки доступа ACS и модерация CharacterWorkflow сохраняют прежний порядок.

## Проверки и ручная приёмка

Выполнены `git diff --check`, `node --check` изменённого JS и `php -l` изменённых PHP-файлов. Ручные сценарии требуют стенда MyBB с доступными, скрытыми и версионированными определениями KB.

1. Создать и сохранить собственную способность в прежнем редакторе.
2. Открыть каталог и добавить готовую способность. Сверить данные карточки с KB.
3. Добавить несколько строк каждого типа и проверить порядок, повторы и предел восьми.
4. Сменить стихию или направление и снова открыть каталог.
5. Сменить оружие и проверить подсказки. Несовместимая карточка должна открываться и копироваться в собственный вариант, но без добавления ссылки на готовую механику.
6. Сохранить смешанную анкету и проверить сохранённые поля и отсутствие копии механики готовой способности.
7. Повторно открыть анкету и проверить порядок, описание, ссылку и доступность.
8. Пройти существующий процесс синхронизации и проверить CharacterSheets.
9. Проверить ссылку и версию в нормализованном профиле и боевом снимке. Отдельно проверить действующие разрешения ACS.
10. Изменить описание и затем механику, скрыть запись и проверить уведомление, поведение нового снимка и неизменность уже созданного снимка.
11. Убедиться, что остальные собственные способности сохранились после повторного редактирования.
