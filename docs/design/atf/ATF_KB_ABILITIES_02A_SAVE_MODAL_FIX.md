# ATF-KB-ABILITIES-02A — Сохранение анкеты и окно каталога

## Причины, установленные по исходникам

- В MyBB 1.8.40 `datahandler_post_insert_thread` вызывается до INSERT новой темы. В этот момент writer ATF может выйти из-за отсутствующего `tid`. Резервный `newthread_do_newthread_end` после #1108 отбрасывает поля со ссылками KB, поэтому успешный POST новой темы мог оставить список несохранённым.
- При редактировании writer ATF работал в предварительном хуке обновления, а затем часть полей повторно записывалась из POST другим хуком. Клиент также заново собирал все собственные способности при submit, даже когда редактировалось только обычное поле. Скрытые числовые поля эффектов оставались включёнными и могли останавливать нативную отправку при нарушении `min` или `step`. Сервер заново проверял текущие требования к стихии у уже сохранённых старых строк.
- Окно каталога было нативным `dialog`, но имело класс обычной модалки KB-чипов. Очистка KB-чипов удаляет все узлы с этим классом напрямую, обходя обработчик `close` каталога. Кроме того, каталог монтировался в `AFModalHost`, который управляет размещением элементов, а закрытие и сетевой запрос оставались на стороне каталога. Совпадение класса связывало два независимых жизненных цикла.

## Исправление

- `initCharacterAbilities()`, `collectAbilityFromRow()`, `syncStateFromDom()` и `sync()` используют фактического владельца hidden input и синхронизируются в capture-фазе submit. Сохраняются исходные строки, которые пользователь не редактировал. Создание своей способности, удаление, эффекты и выбор из KB продолжают обновлять то же поле. При восьми записях выводится пояснение. Скрытые контролы эффекта исключаются из браузерной проверки.
- `af_atf_dh_validate()` для редактирования получает форум и ID темы через сохранённый первый пост. Отсутствующее поле способностей не очищает уже сохранённый набор. Некорректный JSON, превышение лимита, неверный AP и отказ проверки ссылки дают отдельные сообщения MyBB. Неожиданное исключение проверки KB получает `error_id` без вывода SQL и трассировки. Неизменённые собственные строки сохраняются даже при несовпадении старых параметров с новыми правилами. Готовые записи по-прежнему проходят действующую проверку KB и сохраняют `ability_source`, `ability_kb_key` и серверный pin.
- `af_atf_dh_insert_thread()` и `af_atf_dh_update_post()` используют завершающие хуки MyBB. `af_atf_newthread_do_end()` и `af_atf_editpost_do_end()` пропускают повторную запись после успешного штатного writer. Таблица и функция записи остаются прежними. `af_atf_prepare_input_block()` сохраняет POST при предпросмотре и ошибке, а для пропущенного поля способностей подставляет сохранённое значение. CharacterWorkflow и CharacterSheets продолжают читать данные через существующие пути после записи.
- `openCatalog()` использует нативный `dialog` с собственным CSS-классом в `document.body`. Кнопка, Escape, клик за границей окна и выбор используют одну очистку. Она отменяет запрос, удаляет окно и возвращает фокус. Если после выбора достигнут лимит и кнопка открытия отключена, фокус получает кнопка удаления добавленной строки. Открытое окно блокирует скролл, закрытие снимает блокировку без очистки чужих классов.

## Проверки

`git diff --check`, `node --check` и `php -l` выполнены. Сопоставлены точки вызова хуков с исходниками MyBB 1.8.40. AdvancedEditor синхронизирует собственный текст на submit, его обработчики не изменялись.

`NOT_VERIFIED` на warprift.ru остаются фактический сценарий отказа при редактировании, конкретное событие, которое оставляло окно пользователя открытым, и все 12 шагов приёмки. В них входят отправка обычных полей, три состава способностей, предпросмотр и отказ валидации, кнопка/Escape/backdrop, повторное открытие, консоль и синхронизация CharacterSheets с KB.
