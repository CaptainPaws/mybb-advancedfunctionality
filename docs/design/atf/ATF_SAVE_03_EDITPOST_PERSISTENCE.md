# ATF-SAVE-03 — Повторное сохранение анкеты

## Что установлено по исходникам

В старом маршруте `af_atf_dh_update_post()` на `datahandler_post_update_end` прекращал работу без записи и сообщения, если отсутствовал `data['tid']` или вложенный `data['af_atf_values']`, либо повторная проверка через глобальные объекты не подтверждала первый пост. Затем `editpost_do_editpost_end` мог собрать исходный POST заново, пропустить способности KB и очистить другие поля, отсутствовавшие в частичном запросе. Таким образом, при пропуске основного writer пользователь мог получить обычное подтверждение MyBB и увидеть старые значения.

В MyBB 1.8.41 `PostDataHandler::update_post()` подставляет TID/FID из существующего сообщения и вызывает завершающий хук после UPDATE поста. `return_values` содержит `visible` и `first_post`. Стандартный путь ядра сохраняет объект DataHandler. Исходники сами по себе не подтверждают, какой guard сработал на warprift.ru и дошёл ли рабочий запрос до хука. Это остаётся `NOT_VERIFIED`.

## Новый маршрут

1. `af_atf_get_post_context_by_pid()` получает TID и FID из сохранённых поста и темы и сравнивает PID с `threads.firstpost`. Проверки начала редактирования, валидации и завершения используют один источник данных. POST не определяет TID/FID.
2. `af_atf_dh_validate()` обрабатывает только отправленные активные поля форума и оставляет проверенный набор у конкретного объекта DataHandler в памяти запроса. Отсутствующее поле пропускается, намеренно пустое удаляется через writer, снятый checkbox передаёт явный 0. Сохранённые значения дополняют контекст проверки механики и подставляются при повторном отображении формы.
3. `af_atf_dh_update_post()` на `datahandler_post_update_end` сверяет объект, PID, TID и FID и вызывает единственный writer редактирования. `af_atf_editpost_do_end()` теперь только сообщает, если запись не подтверждена. Сырой POST больше не записывается вторично.
4. `af_atf_save_values()` при редактировании записывает изменения через штатную таблицу InnoDB, читает затронутые поля с writer и сверяет их перед коммитом. Подтверждённая запись очищает кэши HTML и текстовых значений только для темы. `af_atf_get_values_by_tid()` использует writer, чтобы повторное открытие редактора и `showthread` видели данные без ожидания реплики. Список полей и кэши KB и CharacterWorkflow не сбрасываются.
5. При ошибке после нативного обновления пользователь получает уточнённое сообщение с диагностическим ID. В журнал попадают только признаки определения контекста, валидации, достижения writer, записи и сверки, а также безопасный код отказа. Текст анкеты и полный POST не записываются в эту диагностику.

Собственные, готовые и смешанные способности проходят действующую нормализацию. Остаются те же серверные данные ссылок KB, эффекты и порядок. Сохранение не создаёт KB-определений и сохраняет существующий порядок синхронизации CharacterSheets.

## Проверки

`git diff --check` и `php -l` выполнены. Сверены исходники хуков MyBB 1.8.41. `NOT_VERIFIED` на warprift.ru остаются создание анкеты, второй и последующие циклы редактирования текста и нескольких типов полей, состояние checkbox, частичный POST, отказ записи и валидации, актуальный showthread и повторное открытие редактора, а также собственные, готовые и смешанные способности.
