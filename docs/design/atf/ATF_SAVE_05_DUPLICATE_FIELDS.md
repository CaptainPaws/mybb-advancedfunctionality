# ATF-SAVE-05 — Один набор полей в editpost

## Источник дублирования

В предоставленном Payload у `editpost.php?pid=651&processed=1` два набора `af_tf[fieldid]` и два `af_atf_form_present`. Значит, браузер отправлял оба блока. Перенаправление MyBB на тему само по себе не подтверждает запись ATF.

В коде были два независимых способа вывести одну анкету:

1. Исторический патчер `af_atf_tpl_force_edit_by_title()` вставлял `<!--AF_ATF_INPUT-->` и `{$af_atf_input_html}` в шаблоны `editpost` и `newthread`. Модифицированный шаблон выводил контролы при интерполяции MyBB.
2. Adaptive Theme Framework предоставляет `<!--AF_COMPOSE_FIELDS-->`. `af_advancedthreadfields_pre_output()` заполнял этот слот тем же HTML без проверки исторической вставки. В composer без слота аналогичная вставка происходила перед редактором. Только обычная ветка MyBB проверяла наличие исторического маркера.

В исторически модифицированном composer эти пути могли сосуществовать. Регистрация нормализатора для процесса восстановления шаблонов при активации не гарантировала удаление пары из каждого действующего пользовательского шаблона при обычном запросе. Порядок «старое значение / новое значение» в предоставленном Payload известен, но привязать значения к конкретной точке рендера на production без исходного HTML нельзя. #1112 и #1113 меняли жизненный цикл диалога и путь записи после POST, сохраняя обе точки вывода.

## Единственная точка вставки

`af_atf_prepare_input_block()` хранит разметку для runtime отдельно. Историческая `{$af_atf_input_html}` разворачивается в пустую строку. `af_atf_insert_compose_fields()` находит форму по нативному действию `do_editpost` или `do_newthread` и заполняет первый слот composer. При отсутствии слота использует позицию редактора composer или строку темы в обычном MyBB. Если строка отсутствует, табличный блок добавляется перед закрытием найденной формы. Маркер результата делает повторный вызов идемпотентным. Остаточные исторические маркеры и повторные слоты внутри формы не порождают контролов.

У checkbox только один контрол с именем `af_tf[fieldid]`. Маркер с отдельным именем сообщает о сознательно снятом флажке. Отсутствие обоих по-прежнему оставляет значение неизменным при частичном запросе. Сохраняются прежние `af_atf_form_present`, prefill token и вложенные скрытые данные анкеты, по одному экземпляру на форму.

## Маршрут записи и проверки

Статически сверена цепочка `af_atf_read_posted_fields()` → `af_atf_dh_validate()` → `af_atf_dh_update_post()` → `af_atf_save_values()` → `af_atf_get_values_by_tid()`. Меняется только формирование и чтение полей запроса. Writer и readback из #1113 сохраняются. Если POST содержит одно новое имя, но тема показывает старое, следует сопоставить `X-AF-ATF-Edit` и диагностический ID из ответа.
