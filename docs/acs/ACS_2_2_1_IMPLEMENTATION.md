# ACS-2.2.1 — сессии, темы и роли

Исходная main: `581f178d0325c4354fa8e2e64dbd8afc41645366`. Реализовано, готово к ручной проверке; принятие остаётся за заказчиком. Design Baseline не изменён. Существа, snapshots, столкновения, раунды, AP и Resolver не реализованы.

## Схема и установка

Используются уже установленные `af_acs_sessions`, `af_acs_session_roles`, `af_acs_operations`, `af_acs_events`, `af_acs_event_details`. DDL и индексы миграции **001_foundation** соответствуют Architecture §5. Новая миграция 002 не требуется; схема остаётся `001_foundation`. Не изменяется checksum прежней миграции. Записи исторических events не обновляются/не удаляются.

После обновления файлов: ACP AF → ACS → Основные → **Обновить / продолжить миграции**. Эта явная команда проверит схему и зарегистрирует группу штатных настроек MyBB **ACS: Сессии**:

- `af_acs_session_gm_groups`: ID групп, которым разрешено создавать сессии вне ACP; пустое значение не предоставляет это право.
- `af_acs_default_member_role`: observer или player; копируется в config_json новой сессии и используется формой назначения. Изменение значения не переписывает конфигурацию существующих сессий.

Активация не выполняет миграции, не сбрасывает настройки и роли. Деактивация сохраняет все данные. Полное удаление остаётся заблокировано при наличии данных.

## Методы и маршруты

`AF_ACS_SessionService::command(operation, input)` поддерживает create, set_role, remove_member, transfer_owner. `view(session_id)` и `list(after)` возвращают только доступные данные. Все команды получают actor из текущей аутентификации MyBB, требуют POST, CSRF, operation_key и причину; изменения требуют expected_version. Роль и expected_version не являются подтверждением полномочий.

Транспорт: существующий AF `xmlhttp.php?action=af_addon_api&addon=advancedcombatsystem&op=...`. GET list/get — чтение; команды — POST. Ответы содержат ok, request_id, data/versions либо безопасную категорию ошибки и error_id. Идентификаторы и BIGINT-версии передаются строками. Предел тела API — 16 KiB; новая запись команды ограничена 20 командами на пользователя за минуту. Подтверждённые повторы возвращаются до проверки лимита, без повторного применения. Чтение ограничено 100 кандидатами с курсором; список участников — максимум 201 строка.

ACP: существующий раздел «Сессии». Пользовательская минимальная страница: `misc.php?action=acs_sessions`, просмотр — с `session_id`. Страница не реализует игровой интерфейс. GET не изменяет сессию, роли или схему.

## Права

| Действие | Серверная политика |
|---|---|
| Создание | ACP AF administrator либо группа из af_acs_session_gm_groups; плюс право просмотра темы |
| Выбор другого owner при создании | Только ACP administrator; выбранный пользователь существует и имеет доступ к теме |
| Просмотр | Сессионная роль либо ACP administrator; обязательно действующие права MyBB на тему |
| Изменение участников | owner/gm либо ACP administrator; только active-сессия |
| Назначение/изменение других мастеров | owner либо ACP administrator |
| Передача owner | Отдельная session.owner.transfer, только ACP administrator, причина/CAS/аудит |
| assistant_gm/player/observer | Чтение; управление существами не предоставляется |
| Закрытие, архив, reopen | BLOCKED до проверки обязательств этапа 10 |

Owner нельзя удалить или сменить обычной командой роли. Новое назначение хранит одну роль участника; обнаруженные неоднозначные прежние строки не исправляются скрытно. Версия существующей строки роли растёт. Удаление участника и последующее добавление создаёт новую membership-запись. GM/administrator не получают права на чужого персонажа; entity/critical permissions последующих этапов остаются deny-by-default.

Проверяются существование темы/форума/пользователя, canview/canviewthreads, canonlyviewownthreads, модерационная видимость, пароли родительских форумов. Для назначения другого пользователя в запароленную тему нельзя подтвердить его cookie в чужом запросе: такое назначение безопасно отклоняется. Права перепроверяются при каждом чтении и команде.

## Транзакции и ATF

Используется существующий TransactionManager и общая write connection MyBB. Изменение проекции, роли, operation, session_version/next_sequence и append-only event/details фиксируются вместе. Повтор ключа с другим payload блокируется. Ошибка откатывает проекцию и аудит вместе. Настройки соединения после операции восстанавливаются — совместимость с ATF сохранена.

ATF provider: owner advancedcombatsystem, key session_link, slot `thread.before_posts`. Только для авторизованных owner/gm/assistant_gm связанной темы. Один ограниченный prepared SELECT, без SQL-миграций, Resolver, KB/CS/Inventory и ассетов. Ошибка необязательного provider возвращает пустую строку, не вызывает MyBB fatal SQL renderer. Шаблоны ATF и ядро не изменены. Обычные темы не получают панели или игровых обработчиков.

## Проверки и ручная приёмка

`tests/acs_sessions_regression.php /tmp/acs221-socket/mysqld.sock` выполняется только на одноразовой локальной MariaDB, создаёт и удаляет собственную случайную БД. Проверяет создание/retry, CAS, аудит, запреты/CSRF/права темы, версии ролей, defaults, реактивацию, настроенную GM-группу, передачу owner, ACP и ATF, отказ необязательной панели при недоступной таблице. Проверено сохранение charset/sql_mode общего соединения. PHP lint затронутых файлов. Локально PHP 8.4.24/MariaDB 10.11; PHP 8.5 и установленное ядро проверяются вручную. Полный suite/E2E не запускался.

1. Выполнить явное обновление ACS в ACP, проверить новые настройки.
2. Создать тестовую тему и сессию; проверить owner, тему, active и версию.
3. Назначить GM и игрока; повторить отправку того же POST — дубликатов нет.
4. Проверить GM-ссылку в теме с ATF и пользовательскую страницу. Проверить запреты обычному пользователю и после утраты доступа к форуму.
5. Проверить передачу owner администратором с причиной, изменение версий и журнал.
6. Изменить default role — прежний config_json не меняется.
7. Отключить/включить ACS: данные и настройки остаются.
8. Проверить обычную тему без сессии, быстрый ответ и AdvancedEditor.

Откат: отключить ACS и revert PR без удаления таблиц. Новые sessions/roles/events сохраняются; старый код их не обрабатывает. Uninstall не применять для отката. При неизвестном результате команды сначала повторить тот же operation_key/POST либо просмотреть сессию; не заменять ключ для слепого повтора. ACS-2.2.2 автоматически не выполняется.
