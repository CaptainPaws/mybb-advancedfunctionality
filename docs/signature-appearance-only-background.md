# ASB 1.0.4 / Appearance 1.6.5: фон, удаление изображений и профиль

## Исправления

AdvancedSignatureBuilder больше не владеет фоном подписи. Удалены четвёртый шаг, `background` из активной модели/seed, выбор фона в JS, background IMG из общего рендерера, его backdrop CSS и добавление фона в переносимый BBCode. Старое поле принимается только для совместимости и отбрасывается при чтении/сохранении. Три дополнительных изображения, Gallery Picker, ссылки и статусы сохранены. Видимая корзина с `aria-label` находится в каждом слоте; она очищает только привязку URL/ID и не удаляет файл из Gallery. Параметры MyBB `updateposts` размещены в компактном disclosure перед последней панелью действий.

Фон из ТЗ задан в `af_aa_signature_defaults()` AdvancedAppearance: `cover`, `center`, без повторения, чёрная маска 40% и светлый текст по умолчанию. Его применяют существующие компиляторы к компоненту подписи во всех контекстах, включая APStudio. Файл не копируется в ASB. Настройки пользовательского компонента имеют приоритет; наличие `background_media_id` (включая `null`) или `background_url` (включая пустую строку) отменяет подстановку стандартного изображения. Существующие маски, шрифты и цвета не переписываются. Настройки вычисляются при компиляции, без массового обновления сохранённых пресетов. Кнопка APStudio «Убрать изображение» сохраняет явный `null`; сброс к исходному изображению снова разрешает стандартный фон.

## Старые публикации

Обновление/активация ASB добавляет nullable `af_asb_signatures.background_backup`. Первоначальные `users.signature`, JSON черновика/публикации и хеш сохраняются там однократно; прежний `legacy_backup` не перезаписывается. Старая резервная таблица APUI не меняется.

Миграция автоматически пересобирает переносимый BBCode только при двух подтверждениях: опубликованный хеш соответствует текущему исходнику, а полная реконструкция прежнего компилятора (включая фоновый IMG) байт-в-байт совпадает с ним. Новая подпись, очищенная модель и её хеш обновляются одним SQL UPDATE с JOIN и проверками прежних значений. Конкурентное изменение подписи/модели не перезаписывается. Произвольные IMG в обычных подписях не ищутся и не удаляются.

При несовпадении исходник не меняется. Публичный рендерер уже игнорирует устаревший фон, а UserCP показывает предложение «Обновить подпись». Обычная публикация проходит MyBB-проверки и сохраняет исходник перед заменой. Если поле резервирования ещё не установлено через ACP, публикация требует обновить аддон. Повторный запуск миграции не заменяет уже сохранённую резервную копию. При изменившихся лимитах или недоступном старом медиа автоматическая пересборка может быть пропущена.

## Почему профиль оставался сломанным

В исходнике MyBB **1.8.40** `member.php` на строках 2153–2154 парсит `$memprofile['signature']` в HTML и формирует native wrapper. Хук `member_profile_end` вызывается позже (строка 2844). Предыдущая интеграция передавала уже распарсенное значение в проверку хеша исходного BBCode; модель отклонялась, а профиль показывал переносимый BBCode через обычный парсер, в том числе прежний огромный фоновый IMG. Предыдущая проверка этого участка ошибочно моделировала `memprofile.signature` как сырой BBCode.

Теперь общий `af_asb_published_html()` получает исходник из существующего JOIN с `users.signature`. Native-видимость остаётся обязательной: скрытая/отключённая MyBB подпись не восстанавливается. Используется UID владельца профиля, общий рендерер, его пресет Appearance и существующий самостоятельный disclosure ATF, свёрнутый по умолчанию. ATF/APUI продолжают размещать готовый компонент; второй реализации композиции в APUI не добавлено. Для обычных подписей сохраняется прежний результат парсинга MyBB.

Перед оценкой внешнего шаблона профиля ASB добавляет только view stylesheet через существующий Theme/File resolver. Проверены реальные ссылки в финальном head в режимах Theme/File/Auto; конструктор и Gallery runtime в профиль не добавляются. `member.php` уже был объявлен в manifest, поэтому повторная регистрация маршрута не требовалась.

Ядро MyBB, AF Core, Gallery, APUI и ATF в этой правке не изменены: используется их существующая инфраструктура.

## Проверки и установка

Проверены PHP/JS-синтаксис, старые модели, план миграции и её SQL-защита от конкурентной записи, повторяемость, сохранение резервных копий, общий HTML четырёх композиций в трёх контекстах, настоящий порядок MyBB с уже распарсенным полем профиля, Theme/File-доставка, область владельца, сохранение пользовательских изображений/явного удаления и Gallery API. Использованы короткие существующие регрессии; длительных браузерных прогонов не было.

После загрузки файлов обновить ASB и Appearance через ACP. Миграция выполняется только при активации/обновлении, а не при чтении профилей. На реальной базе warprift.ru миграция и авторизованные страницы здесь не выполнялись. Финально проверить на сайте три контекста, включая просмотр чужого профиля, корзины/GIF, фон своего пресета и явно удалённый фон.
