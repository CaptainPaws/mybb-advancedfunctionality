# AdvancedAppearance: мастерская постбита (этап 4)

Совместимость: MyBB 1.8.40, PHP 8.5.0. Предыдущие контракты: [архитектура](ADVANCED_APPEARANCE_STUDIO_CONTRACT.md), [Media API](ADVANCED_GALLERY_MEDIA_API.md), [личные пресеты](ADVANCED_APPEARANCE_PERSONAL_PRESETS.md).

## Пользовательский маршрут

`apstudio.php` открывает мастерскую для авторизованного владельца. Постбит — единственный реализованный редактор; остальные категории помечены «скоро». Карточки показывают виртуальный системный стиль, личные записи, свободную ёмкость и ссылку `shop.php` для будущего расширения. Создание, применение, клонирование и удаление используют API этапа 3 с серверными проверками владельца, CSRF и слотов. Миниатюры схематически показывают цвета и шрифты.

`fittingroom.php` без параметров для авторизованного пользователя открывает эту же мастерскую. Старые публичные маршруты примерочной с `do` сохраняются. Старый администраторский каталог доступен через `apstudio.php?mode=catalog`; старые ссылки с `do` тоже работают под прежней проверкой администратора. Магазинные определения, покупки и назначения не мигрируются и не удаляются.

## Схема и серверный контракт

Новые таблицы и колонки не нужны. Расширяется строго валидируемый JSON существующего `schema_version=2`; прежние плоские параметры остаются читаемыми. Новые параметры:

- `display_title`, `description`: обычный текст (название подчиняется ACP; описание до 500 символов). Название и описание публикуются вместе с JSON в одной транзакции. Их черновые значения лежат только в `draft_json`.
- `components`: объект только с `topbar`, `sidebar`, `message`, `signature`. Каждый компонент содержит только поля из `af_aa_studio_fields()`; неизвестные поля и типы отвергаются. Пустые компоненты сохраняются как JSON-объекты.
- `avatar_media_id`: собственное изображение Gallery для аватара постбита.
- `canvas`: разрешённый пресет существующего ElementTheme и числовые параметры `intensity`, `speed`, `density`, `opacity` от 0 до 100; необязательный literal hex `color`. Нельзя задавать canonical key, `enabled` или `surfaces`.

Семейства шрифтов остаются фиксированным реестром этапа 3. Размер 12–24 px, line-height 1.2–2.2, letter-spacing −1–3 px, padding/radius 0–24 px, рамка 0–3 px. Угол градиента 0–360, прозрачность/затемнение 0–1; позиция/масштаб/тени/линии — enum. `null` для полей компонента означает наследование, а для `background_media_id` — явное отсутствие изображения. Кнопка наследования удаляет поле. Отсутствие пользовательских цветов сохраняет существующую стихийную палитру.

ACP-лимиты JSON, названия, слотов и медиа действуют на запись. Начальный лимит медиа остаётся 3; настройка теперь допускает 0–8 уникальных ID (четыре фона, аватар, три прежние фоновые ссылки). Повторение одного ID не увеличивает счётчик. Уменьшение ACP-лимитов не скрывает ранее опубликованные корректные параметры; структурные пределы остаются обязательными.

POST `apstudio.php?api=personal`, `operation=preview`, `settings_json` возвращает `{ok:true,data:{css,canvas}}`. Действуют авторизация, CSRF (проверяется и boolean-результат `verify_post_check(..., true)` MyBB), target contract и Gallery ownership; операция не создаёт пресет/альбом/assignment и не закрепляет файлы. Сохранение и применение продолжают закреплять approved local raster через `ag_retain_owned_media()`.

## Примерочная и публикация

Примерочная подставляет безопасные демонстрационные данные в **тот же исходный файл** `adaptivethemeframework/templates/postbit_classic.html`, который принадлежит ATF. Это не отдельная копия структуры постбита и не вызов публикации сообщения. Фрагменты кнопок, форм, модерации и действий пусты; ссылки перехватываются. Имя/аватар берутся из контекста владельца, звание/статистика/сообщение/подпись демонстрационные. Стихия определяется существующим `af_adaptivethemeframework_post_element()` с approval gate. Пользователь не задаёт её ключ. Локальные ручные изменения установленного DB-шаблона не копируются в демонстрационную сцену: её контракт — принадлежащий ATF исходник.

`af_aa_personal_compile_css()` вызывается и примерочной, и обычным runtime. `af_aa_studio_compile()` выдаёт только ограниченные CSS variables и заранее заданные декларации/селекторы для четырёх существующих узлов ATF. Примерочная добавляет фиксированный scope `#aa-studio-preview`, публикация — класс владельца `af-aa-postbit-user-UID`. Нет пользовательских селекторов, grid/sticky/position/z-index/display, imports или HTML. Порядок: ATF → APUI/ElementTheme → опубликованный personal preset. У канонической ATF-поверхности учтена специфичность стихийного правила; сохранённые плоские цвета этапа 3 тоже перекрывают стандартную палитру. `draft_json` в runtime не читается.

Аватар меняет только `af_atf_primary_avatar` в Appearance hook после композиции ATF; `$post['useravatar']`, профиль и идентичность не меняются. CSS-примерка работает и для стандартного аватара. Существующий postbit CSS подключается на странице мастерской; ownership и структура шаблонов ATF не изменяются.

## Gallery и ElementTheme

Gallery получает response marker `data-aa-gallery-picker`, чтобы существующая asset delivery подключала свой picker на странице без текстового редактора. Используется `AF_GalleryPicker.open(callback,{purpose})`: фоны — `appearance_postbit_bg`, аватар — `appearance_avatars`. Кнопки выбора возвращают `media_id`; загрузка, свои другие альбомы, MIME, thumbnail, quota и lazy albums остаются в Gallery. У Appearance нет файлового хранилища, upload handler или SQL к Gallery. Настройки доступа и blacklist Gallery сохраняют приоритет.

`element-effects.js` принимает server-owned `[data-af-appearance-effects-config]` по UID и публичный `setAppearanceEffects(uid, config)` для живой примерки. Он меняет только декоративные параметры **у уже существующей канонической postbit-поверхности, разрешённой ACP**. Отсутствующая/непринятая анкета остаётся нейтральной. Если ACP не включает postbit Canvas для стихии, выбор в пресете не включает его. Это существенное ограничение существующего ElementTheme, а не повод обходить gate.

Renderer/Canvas Engine остаются единственными: refresh переиспользует зарегистрированные hosts. `effects_enabled`, `effects_postbit`, настройка sidebar и reduced motion сохраняют приоритет. Palette engine не копируется; пользовательские цвета только переопределяют разрешённые свойства поверхности.

## Черновики и адаптивность

Preview обновляется с debounce, ответ старого запроса не заменяет новый. Сохранения сериализованы: создание нового autosave-черновика не дублирует слот, сохранение/возврат/клонирование не обгоняют незавершённый autosave. После изменения через 1.4 секунды сохраняется `draft_json`; опубликованный JSON остаётся прежним. Есть отдельные кнопки сохранения, черновика и сброса к опубликованной версии. При незавершённом запросе localStorage содержит резерв по UID и preset ID; сервер заново валидирует восстановленные настройки. Гость не получает чужой резерв через UI. При успешном сохранении резерв удаляется.

Desktop: настройки и постбит рядом. До 900 px — переключатель настроек/примерочной. Основной форум и grid/sticky не получают правил мастерской.

## Обновление и проверка

Обновить addon через обычный AF upgrade/activate, чтобы зарегистрировать новый шаблон `advancedappearance_workshop` (Appearance 1.2.0). Настройки/таблицы предыдущих этапов должны быть установлены. Новый addon, схема масок и продажа слотов не добавлены. Production DB не изменялась в тестах.

Целевые проверки:

- `tests/appearance_studio_integration.php`: PHP 8.5.0/MySQL 8.4, типы/диапазоны/ownership, общий компилятор, отдельные draft metadata, пустые JSON-объекты, approval/ACP gate; также регрессия API этапа 3 и параллельных слотов.
- `tests/appearance_studio_browser.cjs`: Chromium, карточки/свободный слот, live font/color, восстановление, выбор компонента, inert preview, Canvas без дублей и viewer opt-out, Gallery purpose/ID, сохранение/применение/system reset, mobile, invalid HTTP values, опубликованный стиль/другой UID и неизменность grid/sticky.
- Browser Gallery HTTP fixture минимален; сам picker JS настоящий. Upload/thumbnails/system-album pipeline остаётся проверенным отдельными тестами этапа 2; заново физический upload в Appearance не реализуется.

Изолированный стенд: БД **только `appearance_test`**, префикс `aa_test_`, `AA_TEST_DB_HOST`; после integration запустить PHP built-in server с `tests/appearance_studio_router.php` на 8100 и выполнить browser script. Не устанавливать fixture endpoints на production.

Основные файлы: `advancedappearance/studio.php`, `personal.php`, `advancedappearance.php`, `manifest.php`, `assets/studio.{js,css}`, `templates/advancedappearance_workshop.html`; небольшие интеграционные изменения `advancedgallery/advancedgallery.php` и `advancedelementtheme/assets/element-effects.js`. ATF, ядро MyBB, Shop и Editor не переписываются.
